HunterCode Community 产品说明书与应用方案

版本：2026-09-29 · 适用对象：私募投研团队、专业个人投资者、小型量化团队 产品定位：把搜索、整理、研究、监控与提醒交给智能体；投资决策、指令复核与交易执行由人负责。

1. 从哪里开始

HunterCode 是可自部署的 AI 投研工作台，覆盖 A 股、港股、美股。用户配置大模型与数据源后，可以在对话中查询行情、新闻和公司信息，运行深度分析，管理自选股与持仓，并在策略中心做因子筛选和回测。对话、持仓和投资论点保存在本地数据库。它不连接券商自动下单，也不保证预测准确。

安装与首次配置见 快速开始。部署后打开 /chat，顶部“帮助中心”可随时返回本手册。实际功能受数据源、密钥、市场覆盖和部署配置影响；结果页面应以数据时间与来源为准。

2. 一天的工作流程

盘前：收集与形成观察清单

  1. 请智能体汇总隔夜宏观、公告、行业新闻与自选股事件，要求逐条列来源、发布时间及可能影响。
  2. 对重要公司运行深度分析，核查财务变化、估值、竞争格局和风险，记录“事实 / 推断 / 待验证问题”。
  3. 用策略中心的因子与筛选器形成候选池，再结合流动性、行业集中度及禁止交易名单人工复核。
  4. 产出盘前卡片：关注标的、触发条件、反证条件、数据更新时间、负责人。

可直接提问：

汇总我的自选股过去 24 小时公告和新闻。只列有来源和时间的事实；逐只说明原投资论点是否受影响，并给出今天需要人工核实的三件事。

盘中：观察、核实、提醒

把价格、成交量、资金流、公告或组合暴露设为观察条件。收到信号后先检查数据是否延迟、是否停牌或复权、同一事件是否重复，再让智能体解释与原投资论点的关系。信号是研究线索，不是交易指令。实时性取决于数据源与后台调度；浏览器页面打开不等于全天候稳定监控。

盘后：复盘与更新研究记录

记录当天新事实、原假设状态、组合暴露变化、未完成的问题与次日观察条件。将候选策略的回测结果、参数和数据区间保存到团队研究记录；由人决定是否进入模拟或真实交易流程。

3. 两类应用方案

专业个人投资者

建议从一个自选池、一个持仓账本和一份固定日报开始。先验证数据源稳定性，再使用量化因子缩小候选范围。对每只持仓记录买入理由、失效条件、持有期限与最大可接受损失。智能体每天做信息检索、论点复核和异常摘要；用户负责判断与操作。

私募机构或研究团队

建议把研究拆为“数据采集 → 分析草稿 → 研究员复核 → 投委会/负责人决策 → 交易员执行 → 盘后归档”。按策略、组合、标的和日期组织研究材料；研究结论保存原始出处、数据截面、模型与 SKILL 版本、审阅人。需机构级权限、审批、审计、留痕或合规报告时，应按第 6 节建设扩展能力，并在正式使用前做安全和合规验收。开源社区版当前功能不能替代机构 OMS、PMS 或合规系统。

4. 量化选股、监控与回测

现有工作流

  1. 在策略中心选择市场与股票池，使用官方策略或到因子广场挑选因子。
  2. 在工作台设置因子权重、筛选规则、调仓频率、成本和基准；明确缺失值与行业约束。
  3. 运行回测，查看收益、回撤、换手、成本、分档验证、逐笔交易与数据质量提示。没有实算结果时，不应把策略配置当成业绩。
  4. 比较训练期与样本外、不同市场阶段和交易成本敏感性，再决定是否加入观察池。
  5. 将策略输出视为候选名单，用基本面、流动性、事件风险和组合约束做人工复核。

因子建议与验证口径

现有因子覆盖估值、质量、成长、动量、技术、资金、波动、流动性与规模，实际可用清单以 /strategies/factors.html 和 /api/quant/factors 为准。建议按目标增加下列因子，新增前先定义数据来源与生效时间：

因子方向 示例 验证重点
质量与现金流 经营现金流 / 净利润、应收增长与收入增长差 财报披露时点、行业可比性
成长持续性 连续季度营收增速、盈利预期修正 预期数据授权、修正滞后
估值与质量组合 行业内估值分位 × ROE 稳定性 行业中性化、极值处理
价格与量能 跳空后回补、放量突破、成交额变化 停牌、涨跌停、滑点
风险暴露 波动率、贝塔、尾部损失、拥挤度 组合相关性、压力情景
事件 公告事件、业绩预告、解禁窗口 事件时间戳、禁止未来信息

每个因子至少记录定义、方向、计算窗口、数据延迟、覆盖率、缺失处理、行业和市值中性化方式。检验 IC/Rank IC、分位组合、稳定性、换手和成本，并做样本外与滚动窗口验证。使用当时可获得的成分股和财报数据，控制幸存者偏差与前视偏差。回测收益属于历史模拟结果，不代表未来表现。

量化监控仓库：建议扩展

建设统一的“策略与组合监控仓库”，把策略定义、版本、因子快照、每日候选、持仓快照、信号命中、告警确认、回测任务、数据质量关联起来。建议的最小记录包括：strategy_id、version、market、as_of、data_source、universe_hash、factor_values、portfolio_id、rule_id、severity、status、owner、evidence_uri。保留原始数据时间与处理时间，支持重跑和审计。

监控任务按交易所日历运行，检查数据新鲜度、缺口、异常值、接口错误和调度失败；同一告警去重、分级并记录确认人。可先从盘后批处理与站内信号开始，再接短信、飞书或邮件。通知通道、服务等级、机构级多租户权限和统一告警工作台属于扩展建设内容，不能仅靠安装 SKILL 获得。

5. 用 SKILL 扩展研究方法

SKILL 是 Markdown 方法论，告诉智能体何时使用、先查什么、如何交叉验证和怎样输出。仓库内置 deep_analysis、investor_panel、risk_profile、trap_detector、lhb_analyzer、uzi 等；实际可用能力以当前安装和工具授权为准。用户可在侧栏安装 GitHub SKILL，也可把自定义 SKILL.md 放在 user-skills/<名称>/。详见 用户 SKILL 说明。

建议优先补充这些工作流型 SKILL：

SKILL 输入 输出与边界
盘前研究简报 自选池、持仓、时间窗 带来源的事实、影响、待核实问题
公告影响核查 公告原文、标的与投资论点 关键条款、影响路径、反证条件
投资论点跟踪 原论点、最新数据 假设状态与证据，不给自动买卖指令
异常波动解释 报价、成交、公告、行业行情 多假设解释与数据缺口
组合风险巡检 持仓、基准、风险阈值 集中度、相关性、暴露和阈值命中
因子研究审查 因子定义、回测报告 偏差、稳定性与复现检查清单

一个最小的自定义 SKILL：

name: thesis_review
description: 当用户要求复核持仓投资论点时使用

# 投资论点复核
1. 读取用户提供的原始论点、有效期和失效条件。
2. 检索最新公告、财报和行情；每项事实标注来源与时间。
3. 将结果分为“支持 / 削弱 / 无法判断”，列出缺失数据。
4. 输出需人工核实的问题，不生成交易指令。

SKILL 只定义方法，不会自动新增行情数据、后台任务或交易权限。需要新数据时接入合法授权的数据源或 MCP；需要持续监控时还要实现调度器、状态存储与通知渠道。第三方 SKILL 安装前应审阅代码、来源与许可证。

6. 扩展实施路线

阶段 目标 可验收结果
1. 数据与研究规范 确定市场、授权数据源、时区、复权及来源格式 任一结论能追溯到时间和原始出处
2. 每日工作台 盘前摘要、盘中异常、盘后复盘的 SKILL 模板 人工可复核的日报与观察清单
3. 量化研究 因子版本、策略参数、回测与样本外校验 可重复运行，结果包含成本与质量说明
4. 持续监控 仓库、调度、告警去重、通知、失败补跑 告警有证据、状态、负责人和闭环时间
5. 机构治理 权限、双人复核、审计留痕、备份与恢复 满足机构内部制度和适用监管要求

扩展接口优先复用现有数据源、MCP、SKILL 和量化 API。新增服务应与交易系统隔离；若未来生成下单文件或建议单，必须有人工确认、风控校验和操作留痕。部署到公网时配置登录、初始化口令、TLS、密钥管理和备份；对行情及公告数据遵守服务商授权与使用条款。

7. 验收清单与使用边界

  • 研究输出可看到来源、时间、市场、币种及数据缺口；无法核实的信息明确标注。
  • 自选股与持仓论点能复盘，策略与因子参数可复现。
  • 回测明确股票池、时间区间、基准、成本、调仓规则与样本外结果。
  • 监控发生数据中断时发出系统故障提醒，不把“无数据”解释为“无风险”。
  • 人负责投资判断、交易执行、权限与合规；智能体承担资料搜索、整理、初步分析与提醒。
