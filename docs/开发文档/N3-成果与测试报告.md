## 〇、结论摘要

- **港美股报价真的进得来**：两条市场各取到一次真实报价，`market` / `quote_quality` / `event_time`（**到秒**）
  一路带到 `fin_snapshot`（以前 market 到快照边界就丢了）。
- **报价通道按市场排序**（N0 报告的结论）：A 股 hunter 优先（一期口径**逐字不变**）；
  **港美股改成腾讯优先** —— hunter 网关的港美股 `updated_at` 只到日期、且落后 1~2 个交易日，
  只能展示不得成交（对齐 M8）；顺带把港美股报价的 `source` 从名不符实的 `official` 改直成 `tencent-qt`。
- **`quote_quality` 落库**：A 股 / 港美股实测都**没有买一卖一盘口** → 落 `last_only`；
  `full` 只在来源给出双边盘口时出现。`no_book` 留给（本期不做的）市价单撮合路径。
- **报价拿不到不许返回 0 价**（一期口径保持）；**报价时刻只到日期 → 不落快照、不得成交**（M8 的坑）。
- **港美股标的同步真的写进 `fin_instrument`**：港股每手来自**港交所官方清单**、美股每手 = 1（事实）；
  拿不到来源的标的（每手 / 交易所）**不写**（= `available=false`），实测跳过 2 只。
- **港美股报价可用于成交**：拿真实报价走完 `取快照 → 六条风控 → 撮合 → 记账`，**HK / US 各成交一笔**
  （`fin_trade` / `fin_cash_ledger` / `fin_position` 落行，成交价 = 真实快照价）。
- **港美股本期只接限价单**：市价单在六条风控之前就被拒绝并留痕，**不拿最新价冒充买一/卖一**；A 股市价单照旧。
- A 股全量用例**一条不减少、全部通过**（见 §三⑧）。

### 1.2 港美股报价通道（第一顺位 = 腾讯）

`fin_data._chain_for():408` 按市场给顺序：A 股 `_official_quote → _tencent_quote`（一期口径不动）；
港美股 `_tencent_quote → _official_quote`。依据 N0 §一：

- hunter 网关港美股 `updated_at` **只到日期**（`"2026-09-30"`）、落后 1~2 个交易日 → **不得用于成交**；
- 腾讯通道 `f[30]` **到秒**、免 key、覆盖全市场。

顺带把 N0 §九-4 点名的「`source` 名不符实」改直：以前港美股报价实际来自腾讯 `_free_quote` 却标 `official`，
现在如实是 `tencent-qt`。

**降级路径**：腾讯拿不到才回落网关，并把 `tencent-qt: 腾讯免费通道无数据` 记进 `gaps`；
若网关给的时刻只到日期，`_is_date_only` 分支会**再试一次腾讯**并把结果写进 `gaps`
（港美股那条链腾讯刚失败过，不重复打 —— `tencent_already_failed`）。

### 1.3 快照的盘口质量口径（附 B）

| 值 | 含义 | 本期实际落库 |
|---|---|---|
| `full` | 有盘口（买一 + 卖一都有） | 来源给出双边盘口时 |
| `last_only` | 只有最新价 | **A 股 / 港股 / 美股实测都是这个** |
| `no_book` | 无盘口、按最新价撮合 | 本期不做的市价单路径 |

**「以实测为准，不许想当然」的实测**：`fin_data.quote("00700.HK")` 与 `quote("AAPL.US")` 的
`bid1_price`/`ask1_price` 都是 `null` → `orderbook=false` → `last_only`。
A 股也不例外：`fdc.get_quote("600519")` 实测返回 `bid1: 0.0, ask1: 0.0`（`_dec(0)` → `None`），
所以 **A 股经现有一期链路拿到的快照也是 `last_only`**。
> ⚠️ A 股**有** Level-1 盘口（腾讯 A 股通道给得出），只是**一期拍板的价格来源是 hunter**，
> 而 hunter 的 A 股报价没有盘口；N3 **不动 A 股的价格来源与成交口径**（红线：A 股行为逐字不变）。
> 这一段作为事实记录在案，要不要给 A 股补盘口是另一个决定。

### 1.4 「报价时刻只到日期 → 不得用于成交」（M8 的坑）

`store.is_date_only():60` 与 `apps/api` 的 `_is_date_only` 同一判据（两边各留一份）。
`capture()` 把「只到日期」与「完全没有时刻」**同一处理：不落快照**，并记一条 `no_timestamp` 缺口，
detail 写明「只到日期（YYYY-MM-DD），没有盘中时刻 —— 不得用于成交，不落快照（对齐一期 M8）」。
于是这种报价**不可能**被撮合用到（`take_snapshot` 拿不到快照 → 委托被拒）。

### 1.6 市价单的降级口径

`apps/paper/app/matching/engine.py:249`：`price_type == "market"` 且 `market != "CN_A"` → **直接拒绝并留痕**

## 二、偏离任务书 / 方案的决策与原因

> 无人值守模式（`拍板 §〇`）下遇岔路口按**最保守、最可核对**的选项继续，逐条标注。

1. **港美股报价通道顺序按 N0 结论改成「腾讯优先」**（任务书 §2 明写「按 N0 报告的结论决定第一顺位与兜底通道」）。
   这不是新发明：N0 §一 已判定 hunter 网关的港美股时刻只到日期、只能展示。
   **A 股的顺序不动**（一期口径）。

2. **「报价只到日期」处理成「不落快照」而不是「落库但标脏」。**
   依据是快照层既有契约：`fin_snapshot.snapshot_time` 是**成交用的**数据源时刻，
   「没有时刻」本来就不落行（`09 §六-6`）；「只有日期」是同一类。display 走 api 的 `quote()` 直接取，不受影响。
   好处：这种报价**不可能**被撮合到（而不是「落了但希望没人用」）。

3. **`quote_quality` 用 `last_only` 而不是 `no_book`。**
   附 B 里 `last_only` = 「只有最新价」、`no_book` = 「无盘口**按最新价撮合**」。
   本期港美股**只接限价单**（市价单被拒），没有「按最新价撮合」这条路径，所以快照层面如实记 `last_only`；
   `no_book` 留在取值集合里，给将来真做市价单时用。

4. **`fin_snapshot.quote_quality` 历史行不回填（NULL = 未记录）。**
   N3 之前的 994 行当时没有这个字段，填任何值都是编（红线 §六.1）。

5. **美股交易所走网关（`findata_db.us_quote`）。**
   本地 / 开源版**没有美股交易所清单**（`stock_universe` 在本机是空表），
   拿代码形态猜交易所就是编。网关有档案（实测 `AAPL` → `NASDAQ`），有就用；判不出该标的 `available=false`。

6. **港股 `board` 一律 `hk_main`。**
   港交所官方清单 CSV 只有 `category`（Equity/ETF/REITs），**没有主板/GEM 之分**，
   所以不猜 GEM；`hk_gem` 枚举留着，等有来源再用。

7. **标的同步的「全量」口径**：`stock_universe`（线上有）→ 港股再回落港交所官方清单；
   美股没有本地清单时**返回空并说明**（传 `codes` 可显式同步），不猜一批代码出来。

8. **本机 `paper` / `fin-worker` 重启、`api` 重建镜像。** 三个服务都是无状态（bind mount / 只读挂载 + 具名密钥卷），
   未动 compose、未 `down -v`、未碰 `hca-*` / `xinghe-*` / `hunter-*` 其他容器。

9. **⚠️ 本机 dev 的 api 容器换了个宿主端口（8100 → 8102）。**
   重建后发现 `127.0.0.1:8100` 被**另一个项目**的容器 `xinghe-api-1` 占着（不是本项目，没动它），
   于是用 `API_HOST_PORT=8102` 起回来。**改动只在本次命令的环境变量里，`.env` 没改**；
   容器之间（paper → `http://api:8000`）走 compose 网络，不受宿主端口影响。
