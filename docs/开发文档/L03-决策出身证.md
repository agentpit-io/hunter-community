## 四、「拿不到真值，只能 `NULL`」的清单（红线 5 正靶）

| 列 | 为什么只能 `NULL` | 怎么才能有真值 |
|---|---|---|
| `fin_snapshot.available_at` | 腾讯 `qt.gtimg.cn` / hunter 网关**不返回**「实际可获取时间」，网络可获取延迟也**没测量**（无从证明）。拿 `created_at` / `now()` 填 = 冒充。 | 接一个报 `availableFrom` 一类字段的数据源，或自建带延迟测量的取数层 |
| `fin_snapshot.revision_id` | 行情**没有「修订号」这种东西**（一价即一快照），数据源也不给。编一个自增号 = 造假。 | 接带 `revision` / `version` 的行情源（本仓现有两个都不带） |
| `fin_data_snapshot.revision_id` | 同上 | 同上 |
| `fin_data_snapshot.artifact_ref` | 本系统**没有落盘产物存储**（`raw_ref` 也一直是空）。 | 接入对象存储 / 文件落盘后填 |
| `fin_data_snapshot.available_at` | 同 `fin_snapshot.available_at` | 同 |
| 决策对象 `data_snapshot_id` | 示例策略**只读项目参数、不绑定数据集快照** → 空 → 落库 `NULL`（不编假快照键）。 | `L04` 的策略服务产出数据集快照并绑定（见 §七交接） |

**能推出来、且写清楚的**（不是 `NULL`）：

- `fin_trade.execution_model_version` —— 撮合那一刻从 `load_execution_model` 已知。
- `fin_trade.mode` —— 服务恒 `PAPER`，**撮合时显式写**（不靠「没配就是 PAPER」）。
- `fin_trade.portfolio_version` —— 撮合前读到的 `fin_project.version`。
- `决策对象 decision_as_of` —— 口径 = **决策时刻**（策略只能用到此刻为止的信息），
  `sample.build_decision` 写 `now.isoformat()`；推不出的调用方留空串 → `NULL`。

## 五、`data.snapshot_create` / `data.snapshot_get` 两个入口（`curl` 真调通）

路由挂在**已有**内网数据面 `/api/internal/fin/data/snapshot`（同一个 `X-Hunter-Internal-Key`，
不另起一套）。经演示/dev 栈真实调用（api 容器 host 端口 `8110`）：

```bash
KEY=<api 容器里的 HUNTER_INTERNAL_KEY>

# ① data.snapshot_create
curl -s -X POST http://127.0.0.1:8110/api/internal/fin/data/snapshot \
  -H "X-Hunter-Internal-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"data_cutoff_at":"2026-10-04T01:30:00+00:00","source":"tencent-qt","quality":"ok","market":"CN_A","code":"600519","note":"L03 curl 验收"}'
# → {"data_snapshot_id":"DSNAP-ca1bfcf7b813485698fffbbf", … ,"revision_id":null,
#    "artifact_ref":null,"available_at":null, …}

# ② data.snapshot_get
curl -s http://127.0.0.1:8110/api/internal/fin/data/snapshot/DSNAP-ca1bfcf7b813485698fffbbf -H "…"
# → HTTP 200，同一行
```

**边界路径**（都实测）：

| 请求 | 结果 |
|---|---|
| `available_at` = 当前 UTC 时刻 | **400** `available_at 疑似用当前时间冒充（落在 now() 的 ±2 秒内）…写 NULL…（红线 5）` |
| 缺 `data_cutoff_at` | **400** `data_cutoff_at 必填（没有数据截止时间就不是快照）` |
| `GET` 不存在的 id | **404** `没有这张数据快照：…` |
| 不带内网口令 | **401** |

## 八、给 `L04` 的交接（**`data_snapshot_id` 的最终名字与语义**）

- **最终名字**：`fin_data_snapshot.data_snapshot_id`，形如 `DSNAP-<24 hex>`。`data.snapshot_create`
  返回它，`data.snapshot_get` 用它读回。
- **语义**：一段**不可变、只追加**的数据快照的稳定键 —— 「策略做这次判断时，站在哪一份数据上」。
  五个必需要素是 §10.2 的「数据截止时间 + 来源 + 版本 + 质量 + 产物引用」。
- **L04 要做**：策略服务的**内容哈希 + 版本锁**建立后，让 `StrategyDecision.data_snapshot_id`
  指向一张真实存在的 `fin_data_snapshot`（当前示例策略留空 → `NULL`）。决策对象已经**支持**这个字段
  （`contracts.py` → `to_paper_command` 的 `intent_ref.data_snapshot_id`），L04 只要产出真键即可。
- **注意**：行情 `fin_snapshot`（撮合用的报价）与 `fin_data_snapshot`（数据集快照）**不是一回事** ——
  前者是「成交价的唯一依据」（paper 侧每单现取），后者是「策略看到的数据集」（策略侧冻结）。
  L04 绑的是**后者**。
