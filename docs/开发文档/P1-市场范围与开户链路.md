## 二、迁移 `0036_project_markets.sql`

全文见文件。四段：① 建表 `fin_project_market`（市场集合的唯一真值，PK `(project_id, market)`）；
② `fin_project.currency` **放开为可空**（只放松）；③ 事实回填（`market_scope='CN_A'` 的项目
→ `(project_id,'CN_A',initial_capital,'CNY',opened_at)`，`ON CONFLICT DO NOTHING`）；
④ 权限（`GRANT SELECT, INSERT ... TO fin_paper_rw`，**新表必须显式授权**）；
⑤ `MULTI` 项目的阻塞报告（`RAISE NOTICE`，不报错、不阻断、**不替它编市场**）。

## 三、API 行为（真实 HTTP 响应，api 容器 `127.0.0.1:8110`）

一次性验收用户（`p1-*-…@example.com`，验收后已从库里清掉）。

### 3.1 `GET /api/v1/fin/tiers` —— `markets_supported` / `per_market`

```json
markets_supported: ["CN_A", "HK", "US"]
per_market: {
  "CN_A": {"currency": "CNY", "board_flags": {"main": true, "chinext": false, "star": false, "bse": false, "st": false, "sub_new": false}},
  "HK":   {"currency": "HKD", "board_flags": {"hk_main": true, "hk_gem": false}},
  "US":   {"currency": "USD", "board_flags": {"us_main": true, "us_other": false}}
}
老字段仍在: initial_capital = 10000 ; board_flags = {"main": true, "chinext": true, "star": false, "bse": false, "st": false, "sub_new": false}
```

> ⚠️ **待确认项 Q1**：`per_market.board_flags` 是**产品策略、不是实测数据**，本轮按「最小可用」
> 只开主板，其余一律 `false`（界面会标「本版未开放」）。它**与老字段 `board_flags` 不同**
> （后者是 A 股档位口径、`chinext` 为 true）—— 老字段按要求**逐字不动**，两者并存是有意的；
> 开放哪些板块由用户拍板后改 `tiers._BOARD_FLAGS_BY_MARKET` 一处。

### 3.2 开户传 `markets`（单市场 / 三市场 / 乱序）

**`{tier:"manage", markets:["HK"]}`** → `market_scope='HK'`、`currency='HKD'`、一行 `(HK, HKD, 100000)`：

```
created = True
market_scope = HK | currency = HKD | initial_capital = 100000.0
markets = [{"market":"HK","currency":"HKD","initial_capital":100000.0,"opened_at":"2026-10-03T02:40:12.652706+00:00"}]

DB: prj_f317cae7836342f884836f07 | HK | 100000 | HKD | 2026-10-03 02:40:12.652706+00
```

**`{tier:"play", markets:["US","CN_A","HK","US"]}`（乱序 + 重复）** → 落库顺序恒为 `CN_A,HK,US`：

```
created = True
market_scope = MULTI | currency = None            （≥2 市场：无单一币种）
initial_capital(档位) = 10000.0
markets(落库顺序) = [('CN_A','CNY',10000.0), ('HK','HKD',10000.0), ('US','USD',10000.0)]
DB: CN_A|10000|CNY ; HK|10000|HKD ; US|10000|USD     （每市场各一份档位本金、各用本币）
```

### 3.3 追加市场 `POST /v1/fin/projects/{id}/markets`

**`{markets:["CN_A","US"]}`（现有 `{CN_A}`）→ 200，多一行：**

```
HTTP 200

market_scope = MULTI
markets = [('CN_A','CNY'), ('US','USD')]
note = 追加的市场从此刻开始记账，不回填历史
```

**`{markets:["US"]}`（现有 `{CN_A,US}`）—— 隐含移除 CN_A → 400，行没变：**

```
HTTP 400
{"detail":"只能增加市场，不能减少；要减少请关停旧项目、开新项目"}
DB: CN_A,US
```

### 3.4 `GET /v1/fin/projects/current` 带出 `markets`

```json
{"project": {"market_scope": "HK", "currency": "HKD", ...},
 "markets": [{"market":"HK","currency":"HKD","initial_capital":100000.0,"opened_at":"2026-10-03T02:40:12.652706+00:00"}]}
```

`GET /v1/fin/projects` 列表每一项也带 `markets`（`prj_f317cae7836342f884836f07 active HK -> [('HK','HKD')]`）。

### 3.5 `MULTI` 项目调账本接口不传 `market` → **400**（paper 服务 `127.0.0.1:8299`）

```
不传 market : HTTP 400  {"detail":"该项目有多个市场，请指定 market"}
显式 ?market=US : HTTP 200  market=US | currency=USD
单市场项目不传 market : HTTP 200  market=HK | currency=HKD     ← 行为逐字节不变
```

`_require_project(..., market)` 装在**每个**吃 `market` 的端点上（`get/positions/orders/trades/cash/valuation/latest/funding`），
不是只挡一个接口；`main.py` 另有全局处理兜底，任何漏网调用点也是 400 而不是 500、更不会退回 `CN_A`。

## 五、偏离方案的决策与原因

1. **追加市场的入参语义 = 「目标集合」而不是「新增那几个」。**
   任务书 §3 同时写了「目标集合 = 现有集合 ∪ 传入集合」和「若传入集合不是现有集合的超集 → 400」。
   两条只有在「传入集合是完整目标集合」时才都成立（否则并集永远不会隐含移除、那条 400 无从触发），
   而验收 §四明确要求「**隐含移除 → 400**」这条守门测试必须存在。故按**超集**实现：
   要加 US 就传 `["CN_A","US"]`。响应里 `note` 与 400 文案都把这个口径说清楚了。

2. **追加市场限定 `status='active'`。** 方案未写明。按「旧账本一行都不动」的既有口径，
   给已关停的项目追加市场没有意义（那个账本不再交易），直接 400 并指路「开新项目」。

3. **`per_market.board_flags` 与老 `board_flags` 并存且取值不同**（见 §3.1 的 ⚠️）。
   方案 §3.5 要求老字段不动、新字段按「最小可用」，两者口径不同是有意为之，标 Q1。

4. **`markets_supported` / `per_market` 只定义在 `tiers.build_template` 一处**，
   不在 `GET /tiers` 响应里再抄一份顶层键 —— 同一件事写两处迟早漂。

5. **`0036` 顺手给 `fin_project_market` 授了 `SELECT, INSERT` 给 `fin_paper_rw`。**
   方案没写，但本仓规矩是「新表必须显式授权」（`09 §一`），且 P2 的 `paper.list_projects`
   要读这个集合 —— 不补就是给 P2 埋一个 403。只加授，不给 UPDATE/DELETE。

6. **`test_fin_project_router.py` 的 `uid` 夹具补了一行 `DELETE FROM fin_project_market`。**
   不是新功能，是新 FK 让原来的清理撞 FK 违约（12 个用例 teardown 全红）。不改就是「改动导致既有用例变红」。
