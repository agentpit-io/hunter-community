## 一、做了什么

新增 `db/migrations/0041_memory_core.sql`（134 行，纯 DDL），把「经验 / 证据 / 记忆快照」三件事落成数据。
逐条对齐方案 §二，**只加表、只加索引**、可重复执行、不改历史行、不做回填。

| # | 对象 | 作用 |
|---|---|---|
| 表一 | `fin_experience` | 经验条目 · 唯一真值。`kind ∈ {fact,hypothesis,verified}` × `status ∈ {待验证,已确认,已推翻}` **分两列**；`exposure_scope` / `holdout_tainted` 防评估泄露；`as_of` / `valid_from` / `valid_until` 时间边界；`superseded_by` 指回自己（**不删**） |
| 表二 | `fin_experience_evidence` | 证据行 · 每条经验至少一行。引用 `trd_...` / `rpt_...` / `rpt_...:metric_key` / `SNAP-...` / 外部文档；`UNIQUE(experience_id, evidence_kind, ref_id)` |
| 表三 | `fin_memory_snapshot` | `memory_snapshot_id` 的真值（前缀 **`msnap_`**）。`purpose ∈ {decision,review,holdout}` + `experience_ids TEXT[]`；回放**按 id 取、不重查** |
| 索引 | `fin_experience_lookup` · `fin_experience_evidence_by_exp` | 读路径主索引 / 证据按经验取 |

**四道硬约束**（`CHECK`，本轮「三分可区分」的地基，已机器验）：

- `kind='hypothesis'` ⇒ `status='待验证'`
- `kind='verified'` ⇒ `method IS NOT NULL AND sample_size IS NOT NULL`
- `exposure_scope ∈ {searchable,holdout_only}`
- `kind` / `status` / `source` / `market` 各自枚举

**命名撞车已避开**：本仓 `0023_fin_core.sql:180` 已有一张 `fin_snapshot`（主键 `snapshot_id`、值 `SNAP-...`、**行情快照**）。
本表叫 `fin_memory_snapshot`、主键 `memory_snapshot_id`、前缀 `msnap_`，**不复用** `snap_` / `SNAP-`。已实测两表共存、主键不同。

## 二、偏离方案的决策与原因

### 2.1 授权：**迁移里一条 `GRANT` 都不写**（对齐 §四 的第 3 条 + 方案 §2.4 决策点 D1）

方案 §2.4 的模板是 `GRANT ... TO <经验服务角色>`，追加规则 §四 又说三张表**刻意 `fin_paper_rw` 一行授权都不给**。
两句话一起看，本部署下唯一自洽的落法是 **`0041` 里不出现任何 GRANT 语句**，三条理由：

1. **经验不是账本**（红线「不许新增平行权威」）。这三张表对 `fin_paper_rw` **零授权**是设计要求，
   也是本轮验收项——「唯一入口」最硬的收口就是账本角色连 `SELECT` 都没有。
2. **不新建角色**（D1）。没有「经验服务角色」这个对象，第二条 GRANT 就没有目标。
   记忆服务（R2 起）跑在 api 进程内，与 `app.migrate` 共用同一把连接。
3. **本部署下授权语义由连接身份决定**：api 连的是库属主 `hunter`
   （`pg_roles.rolsuper = true`，实测见 §三.4），对这三张表本就有全权。
   它的读写能力来自**连接身份**，不是来自 GRANT。为凑一句 GRANT 去建新角色只会多一处可出错的地方。

> 与 `0023:426-440` 的关系：那里是「逐表显式 GRANT 给 `fin_paper_rw`」的收口机制，本文件**沿用同一机制**，
> 只是这三张表的授权清单**是空的**。对照组实测：`fin_paper_rw` 在 `fin_trade` / `fin_snapshot` / `fin_order` 上确有授权（§三.4），
> 证明「机制有效」而非「GRANT 全都没生效」。

### 2.2 与两份上游假设**相反**的一刀（Q1，已在追加规则 §三 拍板）

`08 §78-79` / `09 :541` 假设「二期起复用 `user_memory` 当经验库」。本方案 §1.3 判「不够、不复用」，
**另建 `fin_experience` 系列表**；`user_memory` **一行不动**、两库互不读写。用户 2026-10-03 已拍板按「另建」执行。
本轮只落表，`user_memory.py` 一个字节都没碰。

### 2.3 其余照方案执行，无偏离

- 文件内**不带** `BEGIN;` / `COMMIT;`（`app/migrate.py:apply_one` 已把每个迁移文件包在独立事务里，实测正文无事务边界语句）。
- 落应用库 `hunter`，不新建数据库、不新建角色（同 `0023:9-17` 决定）。
- 类型口径沿用 `0023`：比例 `NUMERIC(9,6)`、时间 `TIMESTAMPTZ`、全表无 `float/double/REAL`（扫描只命中注释）。
