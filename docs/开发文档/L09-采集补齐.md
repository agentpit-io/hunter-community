## 二、三条采集链路

### 2.1 新闻 —— 真的按调度进来

```
Temporal Schedule  fin-news-<market>
  → 工作流  fin.news_collect            (apps/fin-worker/app/workflows.py)
  → 活动    activities.collect_news      (打 api 内网端点)
  → api     services/fin/collection.py:collect_news
  → 取数    finance_data_client.get_news (个股新闻 + 公告，含用户自配源)
  → 落库    news  表（增量去重）  ·  采空 → fin_data_gap(kind='no_data', source='news')
```

- **增量去重**：`(code, title, published_at)` 已存在就不插（`news` 表无唯一约束，应用层去重）。
  ⚠️ **去重命中 ≠ 缺口** —— 缺口只在「源一条都没给」时记（这一点是**上线验收当场抓到的 bug**，见 §六.1）。
- **时间字段口径**（与 `L03` 对齐）：`published_at` = 来源标称发布时刻（解析不出 → `NULL`，**不拿 `now()` 顶替**）；
  `fetched_at` = 入库时刻（本模块写 `now()`，**这是真值**）；`available_at` / `revision_id` = **`NULL`**（源不给，红线 5）。

### 2.2 基本面 —— 真的按调度进来

```
Temporal Schedule  fin-fundamental-CN_A
  → 工作流  fin.fundamental_collect
  → 活动    activities.collect_fundamentals
  → api     services/fin/collection.py:collect_fundamentals
  → 取数    quant.financial_store.download_one （akshare 财务指标 → 提炼）
  → 落库    financial_metric   ·  拿不到 → fin_data_gap(source='fundamental')
```

- **增量**：`financial_store.has_metrics` 跳过已有指标的票（每只约数秒，全量重下无意义）。
- **只 A 股**：`financial_metric` **没有市场列**，且现接的只有 akshare 的 A 股财务指标
  （`stock_financial_analysis_indicator`）。港 / 美股 → **如实返回「数据源未接」，且不记缺口**
  （缺的是「没有源」，不是「这一轮没采到」，两回事）。

### 2.3 情绪 —— 表 + 登记口，**数据源未接**

```
POST /api/internal/fin/sentiment        → services/fin/sentiment.py:register_sentiment
GET  /api/internal/fin/sentiment/{code} → read_sentiment（读回）
GET  /api/internal/fin/sentiment        → freshness（行数 + 最新一行）
```

- **表** `fin_sentiment`（迁移 `0053`，**只追加** · `BEFORE UPDATE OR DELETE` 触发器抛异常）；
- **口径**（§6.2 末句）：每行必须带 `model_version`（模型/来源版本）· `evidence_ref`（证据引用）·
  `generated_at`（生成时间）· `quality`（质量标记）· `source`。**缺一个就 400，绝不填默认值**；
- **`sentiment` 可空**：拿不到值就 `NULL`，**不填 0**、**不拿涨跌幅/成交量冒充**（红线 5）。

## 六、偏离方案的决策与原因

1. **缺口判据从「本轮没写进新行」改成「源一条都没给」**（**上线验收当场发现并修掉**）。
   第一版写的是 `if wrote == 0: record_gap(...)`。第一次采 A 股得 45 行、第二次全被去重 → `wrote==0`
   → **又记了 10 条缺口**。那是「增量没新东西」，**不是缺口**。正确判据是 `if not items:`。
   用例如实盯死了这条（`test_news_collection_inserts_and_dedups` 断言第二次 `gaps==0`）。
2. **`_jsonable` 只转 `Decimal`，不转 `int`**（同一轮发现）：`id`（BIGINT）被顺手转成了 `1.0`。
   已修 + 加回归用例（`test_sentiment_json_conversion_keeps_id_int_and_value_float`）。
3. **基本面只排 A 股**：见 §二.2 / §五 —— 不是「少做了」，是**只有 A 股有源**，排港美只是空跑。
4. **新闻 Schedule 三个市场都排**：设计上三市场都支持（A 股 / 港股本机实测都通），美股是**部署侧缺源**，
   排着它是为了让「接好源即生效」；美股采空**如实记缺口**（不静默跳过，也不造假行）。
5. **`fin.news_collect` / `fin.fundamental_collect` 不查交易日历**：新闻 / 财报是「数据刷新」，
   与「今天开不开市」无关（同 `fin.instrument_sync`）。周末/节假日的媒体稿照样有价值。
6. **采集工作流不进「时点」体系**：独立工作流类型（**不塞进 `fin.point_*`**），
   与 `fin.market_etl` / `fin.instrument_sync` 并列；市场用 ETL 那套小写三字母（`cn`/`hk`/`us`）。
7. **控制类 MCP 的模板清单同步 +2**（`scripts/opencode-mcp/runtime_mcp.py`）——
   那两行 `_TEMPLATES` 与 fin-worker 白名单必须一致，`test_runtime_mcp.py` 盯着。
   ⚠️ **若 huntercode 侧也有 `mcp/runtime_mcp.py`，需同步这 2 行**（本机够不到那个仓）。

## 八、遗留问题

1. **美股新闻源在本机未接**（alpaca key）→ 每晚 `fin-news-US` 会为池里的票记缺口。
   接好源即生效（管线已就位），**不需要改代码**。若长期不接，可考虑把 US 从 `news_specs` 里去掉。
2. **`financial_metric` 没有市场列**，所以「按市场分开采集」在库这一层表达不出来 ——
   本段只在**采集侧**按市场过滤（`_valid_code` 形态判定 + `fin_instrument.market`）。真要港美股财报落同一张表，得先给它加市场列（那是另一次迁移，本段不做）。
3. **采集标的 = 自选股（`stocks`）∪ 系统标的（`fin_instrument`）**，不是全市场 ——
   全市场每只票都抓新闻/财报既慢又无意义（方案 §6.1 只要求「增量抓取」）。要扩大覆盖改 `collection_universe` 一处即可。
4. **`fin_data_gap` 的 `kind` 只有 `no_data` / `no_timestamp` / `no_price`**（`0028` 的 CHECK）——
   新闻/财报缺口统一用 `no_data`（语义一致：「源没给这张票数据」）。要区分「新闻缺」与「行情缺」看 `source` 列，够了，**没有为它改 CHECK**（只做加法）。
5. **`available_at` / `revision_id` 三张表都是 `NULL`**：不是 bug，是如实（见 §五）。将来接有这两个字段的源时再填。
