## 一、逐项：前后账本读数（**真实输出**）

> 全部由 `/tmp/l05_evidence.py` 打在 `l05_test` 上（真 `engine.execute` / 真账本表）。
> 项目本金 100,000，标的买入价 10.0000，买入 100 股。

### 1.1 成交量约束（先做这个）——**改参与率，成交量跟着变**

盘口卖挂 **250 股**（`fin_snapshot.ask1_volume=250`），申报 **100 股**：

```
参与率 1.0 → 上限 floor(250×1.0) = 250 → status=filled    filled_qty=100  tick=0.0100
参与率 0.2 → 上限 floor(250×0.2) =  50 → status=pending   filled_qty=0    tick=0.0100
   pending_reason: 成交量约束：盘口量 × 参与率 0.200000 = 50 股 < 委托 100 股，
                   整笔不成交（part_fill=false），挂单等待
```

- 买入看卖盘挂量 `ask1_volume`、卖出看买盘挂量 `bid1_volume`（「此刻能接走多少」）。
- **盘口量算不出**（快照没有盘口量 / 港美股 `last_only`）→ **不加约束**（不拿最新价顶替）。
- **没配参与率**（现有项目列为 NULL）→ 无约束，**行为与改造前逐字节一致**。

### 1.2 部分成交——**开关开：真的 partial + 剩余挂着**

`part_fill=true` + 参与率 0.2 + 盘口 250 股 + 申报 100 股：

```
回执：status=partially_filled  filled_qty=50  price=10.0000
      pending_reason=成交量约束：… = 50 股 < 委托 100 股；本次成交 50 股，剩余 50 股仍挂着

fin_order  : {status: 'partially_filled', qty: 100, filled_qty: 50, frozen_amount: 500.0050}
fin_trade  : {qty: 50, price: 10.0000, amount: 500.0000, total_fee: 5.0050}
现金       : 可用 98994.9900  冻结 500.0050  |  open_buy_frozen 500.0050
```

- `frozen_amount` 从整笔的 1005.0050 减成本次付出 500.0050 → 剩余 500.0050 留给还没成交的
  50 股；**对账的 `frozen_matches_open`（冻结额 = 未成交买单占用之和）因此仍平**。
- **开关关着（默认 `false`）→ 整笔或挂单**，不改数量、不写 `partially_filled` ——
  老用例一条不变（见 §三）。

### 1.3 停牌——**停牌即拒单，理由可见**

```
人工登记后下单：
  status=rejected
  decline_reason=6747078 已停牌，拒绝委托（停牌原因：重大资产重组；来源：manual；
                  登记于 2026-10-04 19:10:30.000700+00:00）
```

登记口 `POST /api/v1/instruments/{code}/halt`（写入 `halted / halted_reason / halted_at /
halted_source='manual'`）；`halted=false` 解除。风控在**六条之前**先读它（`risk/halt.py`）。

### 1.4 公司行为——**分红入现金 / 拆股调股数与成本**

买入 100 股后（`fin_position`：qty 100、avg_cost 10.0000）：

```
分红 每股 0.50 → cash_delta=50.0000  qty_delta=0  source=manual
  现金可用 before 98994.9900 after 99044.9900（+50.0000）
  最新流水: {kind: 'adjust', amount: 50.0000, available_after: 99044.9900,
            memo: '公司行为·分红 6747078（每股 0.50）'}
  fin_position 不变（qty 100, avg_cost 10.0000）

拆股 2:1 → qty_delta=100
  fin_position after: {qty: 200, sellable_qty: 0, avg_cost: 5.0000}   ← 总成本 1000 不变
  fin_corporate_action（只追加）:
    {action_type: 'split',    qty_delta: 100, cash_delta: 0.0000, source: 'manual'}
    {action_type: 'dividend', qty_delta: 0,   cash_delta: 50.0000, source: 'manual'}

对账 passed=True（0 项未通过）
```

登记口 `POST /api/v1/corporate-actions`（登记即应用，`source='manual'`）。
**对账的「持仓 = 成交净额」把 `qty_delta` 算进去** —— 否则一次拆股就会让账本假不平（见 §五-3）。

## 三、「一条不减少」的证明方式（part_fill 默认不动）

`part_fill` 默认**仍是 `false`**（红线 13：不预写阈值当既成事实；方案明确「默认值不许改」）。
`participation` 默认 `NULL`。两条合起来保证 **A 股全部老路径行为逐字节不变**：

- `match(..., participation=None)` → 不加成交量约束（与改造前同一分支）。
- `resolve_tick` 解析值与全局值**数值相等时回落全局值本身**（`Decimal('0.0100')` 而不是
  `Decimal('0.01')`）—— 保刻度，`10.0100` 不会被渲染成 `10.01`（实测 `test_resolve_returns_global_object_when_equal`）。
- A 股市价单成交价、涨跌停价、回执照旧。

**A 股行为等价**由现有用例钉住（`test_ledger_e2e` / `test_risk_*` / `test_order_intl_e2e`
全部通过，数量未减）。

## 四、偏离方案的决策与原因

| # | 事 | 决定 | 原因 |
|---|---|---|---|
| 1 | 停牌进了风控规则清单（原六条 → 七条） | `risk/halt.py` 作为**第一条**规则 | 方案要求「风控**先读它**」。改了 `test_all_six_rules_run` → `test_all_rules_run`（断言 7 条，新增规则是**加**不是减弱；用例数不变） |
| 2 | 公司行为事件表带 `project_id` + `qty_delta` / `cash_delta` | 一行 = 一次公司行为**在某项目上**的登记与应用，存**实际应用的账本效果** | 效果是项目级（`fin_position` 按项目）；存效果值让对账与审计**可复算**（只看 ratio 得重放全序列才能推当时持仓） |
| 3 | 对账的「持仓 = 成交净额」加公司行为 `qty_delta` | 改 `recon.py` 的那一条查询 | 公司行为改持仓但**不产生成交** —— 不改本项，一次拆股就会让账本假不平。这是必要修正，不是放宽 |
| 4 | tick 三级解析 + 数值相同时回落全局值 | `app/tick.py` | 方案要求「只加列/加行，不改老行为（老数据回落现有全局值）」。**回落全局值本身**是为了刻度一致、回执渲染逐字节不变 |
| 5 | 公司行为**登记即应用**、**不改账户版本** | `apply_corporate_action` 在同一事务里落账务 + 事件 | `fin_project.version` 的口径是「成交笔数」（对账第 6 项核它）—— 公司行为不是成交，动版本会让对账不平。数据源接入后可加「按 ex_date 批处理」的应用器（见 §六） |
| 6 | 成交量约束 / 部分成交**共用一个纯函数** | `match(..., participation=)`；`part_fill` 决定超上限时是「挂单」还是「部分成交」 | 红线 11：两臂共用一套撮合假设。**开关关着时超上限 = 整笔挂单**（不改数量），正是方案要的「整笔或挂单」 |
| 7 | 港股 tick 分档来自 HKEX 公布口径 | 迁移 0050 种下（见 §六-3） | 方案要求「港股逐价位区间」；表按公布口径落，**上线前须联网复核**（本机无法联网核实，如实标注） |
| 8 | `part_fill` 的**执行**默认值 | 保持 `false`（方案/红线 13 明令不许改） | 测试里要验 partial 时，用**用例事务内**（不提交）临时置 `true` —— 不污染别的用例 |

## 五、边界与风险（本段特别守的）

- **红线 11（两臂同条件）**：撮合改动全在一个纯函数里，真实臂与影子臂都调它、传同一份
  参与率与 tick（§1.7 贴证据）。**影子臂禁止订单出口**（红线 12）不变 ——
  `test_shadow_never_touches_the_order_executor` 零调用继续通过。
- **账本只追加**：`fin_trade` / `fin_cash_ledger` / `fin_corporate_action` 一律只 INSERT；
  `fin_corporate_action` 带 `BEFORE UPDATE OR DELETE` 触发器（照 0043/0049 的做法）。
  `fin_order` 的状态变更走既有事件式写法（`UPDATE status/filled_qty/frozen_amount` ——
  0023 的 GRANT 注释：`fin_order` 的 UPDATE 只用于状态列；`frozen_amount` 是「这笔还冻着多少」，
  属订单当前状态）。
- **不许编停牌 / 公司行为数据**（红线 5）：只做表 + 账务 + 人工登记口，`source` 一律 `manual`。
- **`fin_paper_rw` 权限自检不放松**：新表显式 `GRANT SELECT, INSERT`（不给 UPDATE/DELETE），
  与既有账本表同口径。

## 七、遗留问题与给 `L06` 的交接

### 7.1 遗留

1. **公司行为只能整项目应用**：`apply_corporate_action` 作用于「该项目该标的的全部持仓」。
   两个项目持同一只票要各登记一次（当前无数据源、人工登记，可接受；接数据源后改批量应用）。
2. **分红为税前**（未扣股息税）：港股 / A 股的红利税随持股期变，数据源没有 → 如实不扣，
   `memo` 与文档写明口径。
3. **拆股 / 送股的小数股处理**：`floor`（只给整股，不产生碎股）；碎股现金补偿（港股常见）
   未做 —— 无数据源，不编。
4. **停牌只挡「新委托」**：已挂着的单在停牌期间不会被自动撤（`expire` 按收盘撤）。
   要不要「停牌即撤挂单」是产品决定，留给后续。
5. **HK 价差表待联网复核**（§六-3）。

### 7.2 给 `L06`（凭证分离 + 执行允许名单）

- 本段新加的两个**写入口**（`/instruments/{code}/halt`、`/corporate-actions`）是**账本级写操作**，
  `L06` 做「执行允许名单」时应把它们纳入「谁能写账本」的边界考量（它们不走下单路径，
  但同样改账本）。
- `paper` 的写端点鉴权沿用 `require_internal_key`；`L06` 分离行情 / 下单凭证时，
  这两个端点归到「执行侧凭证」还是「管理侧凭证」由 `L06` 定。
