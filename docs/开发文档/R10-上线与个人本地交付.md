### 4.1 关键点：`ports: !override`

解析后**每个服务只剩一条、`host_ip=127.0.0.1`**：

```
web       host_ip=127.0.0.1  3230->3000
```

## 五、修过的两个问题

### 5.1 【**代码缺陷** · 走新 tag `v1.6.0`】`stop_loss_pct` 正负号口径不一致

- **现象**：`R6` 的白名单把 `stop_loss_pct` 写成**正号**范围 `[0.005, 0.5]`（`tighter_when='smaller'`），
  而档位模板（`apps/api/app/services/fin/tiers.py`）与向导写进 `fin_param.stop_loss_pct` 的是**负数**
  （`-0.04` / `-0.03`，与另两条熔断线 `daily_loss_halt_pct` / `account_drawdown_halt_pct` 同口径）。
  `normalize_candidate` 会校验候选配置的**每一个键**，于是候选里带着 `stop_loss_pct=-0.04`
  一进门就被范围检查拒掉。
- **实测本机库**：`fin_param` 共 1312 行，其中 **1294 行 `stop_loss_pct = -0.04`**，
  只有 1 行是 `R9` 当时为跑通演示手工归一成 `+0.03` 的例外。
  **即：任何向导开出来的真实项目都提不出提案。**（`R9` 成果文档 §六-1 记的「跨阶段缺陷」，本轮实测复现。）
- **改了什么**：`_STRATEGY_FIELDS["stop_loss_pct"]` 改成**负号口径** `[-0.5, -0.005]` + `tighter_when='larger'`
  （越接近 0 = 越早离场 = 越紧），与两条熔断线的写法**逐字同源**；按 `R6` 自己的规矩
  「改白名单任何一项 = 换版本键」把 `ALGO_VERSION` 由 `evolution-algo-v1` 升到 **`evolution-algo-v2`**。
  **不需要数据迁移** —— 存量行立刻可提案。
- **怎么验的**：新增回归用例 `test_stop_loss_pct_uses_fin_param_sign_convention`（直接拿档位默认值
  `-0.04` / `-0.03` 断言通过，正号与越界值仍被拒）；`R6`/`R7`/`R8` 的既有白名单 / 影子 / 生效用例
  **12 处**跟着改成负号口径（**只改数据，不改断言逻辑**）。
- **结果**：`apps/api` 全量 **858 passed / 0 failed**（真库），`apps/fin-worker` **207 passed / 0 failed**。
- **提交**：`a1761d0 fix(fin/evolution): stop_loss_pct 白名单改回负号口径 · 修掉「向导项目提不出提案」`
  → 随 `v1.6.0` 发布、演示站已拉到；演示站十二条场景的提案路径（S4/S8/S9/S10/S12）就是在这版上跑通的。

### 5.2 【**交付物内解决，不改代码**】个人部署的两个坑
