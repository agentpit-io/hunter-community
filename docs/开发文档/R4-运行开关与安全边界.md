## 一、做了什么

四个运行开关**落在 API 服务端**（不是前端隐藏按钮），`paper` 模式的前置依赖缺失即降级 `observe`，
并把「能不能进 paper」这条事实做成一个只读接口；同时把 `03 §3` 要求的备份与恢复演练做了一遍。

| # | 落点 | 作用 |
|---|---|---|
| 1 | `apps/api/app/services/fin/switches.py`（**新增**） | 四个 `FIN_*` 开关的**唯一读点**：读值 / 校验 / 硬开关拒绝 / `paper` 前置依赖探针 / 降级判定 |

| 3 | `apps/api/app/routers/fin_memory.py`（两个写 handler +503 分支） | `MemoryDisabledError` → **HTTP 503**，与「请求不合法」的 400 分开 |
| 4 | `apps/api/app/routers/fin_runtime.py`（**新增**） | `GET /api/v1/fin/runtime`：前端的**唯一**取值来源，只读、无副作用 |
| 5 | `apps/api/main.py`（+`include_router` + 启动日志） | 挂上运行时路由；启动时把开关状态（含硬开关违规）打进日志 |

## 二、偏离方案的决策与原因

### 2.1 硬开关选「拒绝请求」而不是「拒绝启动」

`03 §2` 允许「拒绝启动**或**拒绝请求，**并在日志与接口里写明**」。这里选**拒绝请求**
（`GET /api/v1/fin/runtime` → **503**，启动时另打一条 ERROR 日志）：

- 「并在日志**与接口**里写明」这半句只有进程活着才做得到 —— 拒绝启动会让这台机器只剩一条日志，
  运维得 `docker compose logs` 才知道发生了什么；而接口返回的 503 里那句话，前端（R9）可以直接展示。
- 两者都留痕：启动 ERROR（§六.4）+ 接口 503（§六.4）。**没有静默放行**。

### 2.2 `MemoryDisabledError` 不是 `MemoryValidationError` 的子类

「经验库没开」与「这条经验不合法」是两件事：前者修 env、后者改请求。所以给了一个**独立异常类**，
路由翻成 **503**（不是 400）。子类化会被现有 `except MemoryValidationError` 先接住、错报成 400。
`test_fin_switches.py::test_disabled_error_is_not_a_validation_error` 盯着这条。

### 2.3 开关**每次调用现读环境变量**，不在 import 期缓存

- 部署上 `docker compose up -d` 之后进程重建、环境本来就会变，缓存没有收益；
- 测试要在同一个进程里切 env 验「开 / 关」两条路径，缓存会把这件事变成不可能；
- 缓存一份只会让「改完 env 却不生效」看起来像代码没部署。

### 2.4 `conftest.py` 把测试套件的 `FIN_MEMORY_ENABLED` 默认成 1

代码默认是 **0**（fail-safe，`R4.md` 明确要求）。但 R2/R3 的 40+ 条用例测的是**开着的**经验库
（读写、硬过滤、冻结、通电）。若不在 conftest 里 setdefault 成 1，它们会在默认 0 下全部得到空结果。
用 `setdefault` 而不是直接赋值：`FIN_MEMORY_ENABLED=0 pytest tests/` 仍能覆盖它；
「关着的行为」由 `test_fin_switches.py` **显式清空该变量**来验。**没有删改任何既有用例**。

### 2.5 `paper` 依赖探针在 R4 只判「部件在不在、通不通」

`03 §2` 列了五个依赖（模拟账本 / 市场日历 / 行情快照 / 策略决策器 / 验证调度）。
它们的**能力是否足够**（影子臂算不算得出来、两臂同快照口径对不对）是 R6–R8 的事。
R4 每个依赖配一个**真实读取**的探针（不打桩、不读缓存键），语义逐条写在各自 docstring 里，
**不把它当成更强的承诺**。请求的不是 `paper` 时不跑探针（前端轮询不该每次打 5 个探针）。

### 2.6 fin-worker 收到四个开关但**不读**

`R4.md` §一.1 要求 compose 的 api / fin-worker 两段都加 `environment`。worker 侧**没有**读点
（读点只有 api 的 `switches.py`，这是「读口唯一」的硬要求）。透传的目的是让 `.env` 只有一份值；
执行侧要知道**生效**模式（可能被降级）时，去问 `GET /api/v1/fin/runtime`，不照原始值自己判断。
compose 注释里写明了这点。

## 三、四个开关的口径（默认值 + 硬开关）

代码默认值全部取安全的一侧（`switches.py:47-52`）：

```python
MEMORY_ENABLED_DEFAULT = "0"
EVOLUTION_MODE_DEFAULT = "off"
AUTO_APPLY_DEFAULT = "0"
LIVE_ORDER_DEFAULT = "0"
```

| 环境变量 | 取值 | 默认 | 生效语义 |
|---|---|---|---|
| `FIN_MEMORY_ENABLED` | `0` / `1` | **`0`** | `0` ⇒ `memory.query` 返回空集合、`memory.append_evidence` 拒绝（503） |
| `FIN_EVOLUTION_MODE` | `off` / `observe` / `paper` | **`off`** | `paper` 依赖缺一 ⇒ 降 `observe` + 原因（见 §四） |
| `FIN_AUTO_APPLY` | **只允许 `0`** | **`0`** | 非 `0` ⇒ 服务端 503 拒绝，写明「本方案恒为 0，自动生效未交付」 |
| `FIN_LIVE_ORDER_ENABLED` | **只允许 `0`** | **`0`** | 非 `0` ⇒ 服务端 503 拒绝，写明「本项目没有实盘订单出口」 |

非法值（含空串 / 大小写外 / 数字越界）一律**回落到安全默认值并 `logger.warning` 留痕** ——
与 `config.review_delay_minutes()`（R3）同口径：配置写错不该让保护悄悄变了。

## 四、降级口径与探针真值表

`FIN_EVOLUTION_MODE=paper` 时逐个跑五个探针（`switches.paper_dependency_checks`）：

| key | 中文名 | 探针（真实读取） | 未就绪时的 `detail` |
|---|---|---|---|
| `paper_ledger` | 模拟账本 | `GET {PAPER_BASE_URL}/healthz` → `ok && mode=="PAPER" && ledger_db` | `…/healthz 不可达（ConnectError）` / `模式不是 PAPER` |
| `market_calendar` | 市场日历 | `count(*) FROM fin_market_calendar WHERE trade_date >= CURRENT_DATE AND is_trading > 0` | `今天起没有任何已加载的交易日` |
| `quote_snapshot` | 行情快照 | `count(*) FROM fin_snapshot WHERE created_at > now() - 90d > 0` | `近 90 天没有任何行情快照` |
| `strategy_decider` | 策略决策器 | `count(*) FROM fin_param WHERE jsonb_array_length(strategies) > 0` | `没有任何项目配置了策略` |
| `validation_schedule` | 验证调度 | `count(*) FROM fin_job WHERE type IN ('strategy_run','trading_point') > 0` | `验证 / 时点调度没有任何执行记录` |

任一 `ok=false` ⇒ `evolution_mode` 报 `observe`，`degraded_reason` 形如
`进入 paper 模式的前置依赖未就绪 → 已降级 observe：<中文名>未就绪（<detail>）；…`。
库整个连不上时四个库探针一律记未就绪、原因写「数据库不可用」，**不抛异常**（连不上库本就该降级，不是 500）。
**绝不用历史成交顶替影子结果**（`03 §2` 明令，红线 5）。
