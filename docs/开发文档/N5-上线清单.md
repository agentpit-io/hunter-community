## 0 · 前置检查（一分钟，别跳过）

```bash
cd <演示站上的 hunter-community 仓库目录>      # 通常是 ~/hunter-community 或 /opt/hunter-community
git status --short                             # 必须干净；有本地改动先 `git stash`
df -h /                                        # ⚠️ 根分区要留 ≥ 3 GB
docker compose ps                              # 记下升级前的状态，回滚时对照
grep -nE '^(HUNTER_VERSION|FIN_TAG)=' .env     # 记下**升级前**的两个值（回滚要用）
```

- **磁盘不够**：先 `docker builder prune -f`（回收 build cache，不动运行中镜像），再 `docker image prune -f`（悬空镜像）。
  **不要在演示站上 `docker build`** —— 它的根分区只有约 12 GB 余量，`web` 镜像构建本身就要 1.6 GB。
  演示站上一切镜像都从 GHCR **拉**。
- **确认镜像已在 GHCR**（在任意能上网的机器上）：

```bash
for s in api web opencode llm-shim paper fin-worker; do
  docker manifest inspect ghcr.io/agentpit-io/hunter-community-$s:1.4.0 >/dev/null 2>&1 \
    && echo "$s:1.4.0 OK" || echo "$s:1.4.0 MISSING"
done
```
  > 本机实测 2026-10-03：六个镜像 **全部 OK**（`v1.4.0` 与 `1.4.0` 两个 tag 指向同一 manifest）。
  > 若有一个 MISSING，**先停下**（CI 没跑完 / 发版失败），别在缺镜像的情况下 `up -d`。

## 1 · 改 `.env`（**两行都要改**）

```diff
- HUNTER_VERSION=1.3.1
+ HUNTER_VERSION=1.4.0

- FIN_TAG=1.3.1
+ FIN_TAG=1.4.0
```

**为什么 `FIN_TAG` 也必须动**：本期 `paper`（账本/风控/撮合）与 `fin-worker`（调度/工作流）
的代码都改了，它们的镜像标签跟的是 `FIN_TAG`，不是 `HUNTER_VERSION`。
只改 `HUNTER_VERSION` 会让 api/web 升到 1.4.0、paper/fin-worker 停在 1.3.1 ——
**报告会按新口径出、账本按旧口径记**，是最糟的一种不一致。

> 如果 `.env` 里这两行被注释掉了，不用加 —— `docker-compose.yml` 的默认值本期也已改成 `1.4.0`。
> 但**显式钉版本更好**（浮动标签会让下次升级悄悄漂）。

## 2 · 拉镜像 + 起服务

```bash
cd <仓库目录>
git fetch origin --prune && git pull --ff-only origin main

# 主站四个服务（本期 api / web 改了；llm-shim / opencode 也一并拉，保持版本一致）
docker compose pull postgres redis api web llm-shim opencode
docker compose up -d postgres redis api web llm-shim opencode
```

**如果演示站启用了智能交易（`fin` profile）**，再拉这两个（`FIN_TAG` 决定）：

```bash
docker compose --profile fin pull paper fin-worker temporal temporal-ui
docker compose --profile fin up -d paper fin-worker temporal temporal-ui
```

**顺序不要颠倒**：先 `postgres` 起好，再 `api` —— 迁移由 api 启动时跑，它需要库在线。

> `up -d` 会不会 Recreate？会（镜像变了必然 Recreate）。
> 这几个服务里 **只有 `postgres` 有状态且已挂具名卷**；api / web / llm-shim / opencode 都挂卷或本来无状态。
> **`opencode` 的会话正文在具名卷里**（一期事故后已修），Recreate 不丢。
> ⛔ **任何时候都不许 `docker compose down -v`**。

## 3 · 迁移 `0029`–`0035`（**自动执行**，只需确认）

迁移随 `api` 启动自动跑（`python -m app.migrate`，advisory lock 串行化）。
**它们只做加法**：`ADD COLUMN IF NOT EXISTS` / `CREATE TABLE IF NOT EXISTS` / 放松 CHECK 约束；
历史行按 `'CNY'` / `'CN_A'` 回填 —— 现有账本全是 A 股，**回填是事实不是猜**。

### 怎么确认它跑了

```bash
docker compose logs api --since 10m | grep -E '迁移|migrate'
```

期望看到（数字以演示站实际为准，关键是 **`本次待执行 7 个`** 与 `0029`~`0035`）：

```
迁移 | ② 增量迁移（db/migrations）：共 36 个迁移文件，已应用 29 个，本次待执行 7 个
迁移 |   [1/7] 0029_market_scope.sql 完成
迁移 |   [2/7] 0030_market_rule.sql 完成
迁移 |   [3/7] 0031_ledger_currency.sql 完成
迁移 |   [4/7] 0032_fee_stamp_side.sql 完成
迁移 |   [5/7] 0033_snapshot_quote_quality.sql 完成
迁移 |   [6/7] 0034_schedule_ledger_market.sql 完成
迁移 |   [7/7] 0035_report_market.sql 完成
迁移 | ② 增量迁移完成：本次执行 7 个
```

**如果看到「迁移失败，api 不会启动」**：api 停在启动阶段（不会半死不活），
日志里给出文件名与行号；修好或回滚后再起。

## 4 · 健康检查（期望输出逐条对上）

```bash
curl -s localhost:8100/api/health                       # api
curl -s localhost:3100/                                 # web（返回 HTML）
curl -s localhost:8200/healthz | head -c 200            # paper（脚本里的 paper 端口见 .env）
curl -s localhost:8399/healthz | head -c 400            # fin-worker
```

期望：

```
api         → {"status":"ok", ...}                     HTTP 200
web         → <!DOCTYPE html> …                        HTTP 200
paper       → {"ok":true,"mode":"PAPER","mode_fixed":true,"ledger_db":true}
fin-worker  → {"ok":true,"schedules":24,"markets":["CN_A","HK","US"], ...}
```

**`mode":"PAPER"` 与 `mode_fixed":true` 必须都在** —— 这是「不许移除实盘隔离」红线的机器化检查。

再确认市场日历真的落了库（**这条是本期的核心**）：

```bash
docker compose exec postgres psql -U hunter -d hunter -c \
  "SELECT market, trade_date, is_trading, calendar_source
     FROM fin_market_calendar WHERE market <> 'CN_A' ORDER BY trade_date DESC LIMIT 20;"
```
期望：`HK` 行 `calendar_source = hkex_official`、`US` 行 `nyse_official`（不是 `akshare`、不是空）。

## 6 · 回滚（**数据不需要回滚**）

```bash
cd <仓库目录>
# 把 .env 改回升级前的两个值（第 0 步记下的）
sed -i 's/^HUNTER_VERSION=.*/HUNTER_VERSION=<上一版>/; s/^FIN_TAG=.*/FIN_TAG=<上一版>/' .env
docker compose pull api web paper fin-worker
docker compose up -d api web paper fin-worker
```

- **数据不回滚**：本期迁移只加列 / 建表 / 回填，**没有一行历史被改或删**。
  旧镜像读新库没问题（旧代码只 SELECT 它认识的列，多出来的列它不关心）。
- 回滚后报告 id 会回到旧算法（不含市场段）—— 1.4.0 生成的报告在列表里仍能打开，
  只是重跑同一天时会回到旧 id 那一行。**这不是数据丢失**。
- ⛔ 回滚**不要** `docker compose down`；直接 `up -d` 覆盖即可。
