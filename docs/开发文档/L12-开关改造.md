## 〇、人话目标

产品定位是「**AI 自己学、自己改、自己跑，人工只在想干预时介入**」。改之前有两件事跟它拧着：

1. 新装一台机器，默认**不学习**（代码默认 `FIN_MEMORY_ENABLED=0` / `FIN_EVOLUTION_MODE=off`）；
2. 「自动生效」被做成**硬锁死**（`FIN_AUTO_APPLY` 必须为 `0`），界面上只有一行「恒为关闭」的死文字。

本段把默认值改成「开」，把自动生效从**硬锁死**变成**可开可关的真开关**（含按项目开关）。

> ⚠️ **本段结束时，系统仍然不会自己生效任何东西。** 见 §二.1 的副作用说明。

## 二、偏离 / 需要如实理解的决策

### 2.1 ⚠️ 必然的副作用：生效入口不再被 `FIN_AUTO_APPLY` 拦，但仍要 `confirm=true`

`FIN_AUTO_APPLY` 从硬开关名单移出后，`apply_proposal()` 里那道 `switches.assert_hard_ok()`
**不再**因为 `FIN_AUTO_APPLY` 非 0 而拒绝。**本段一个字没动 `evolution.py`**（任务书明令），
所以生效入口**仍然要求调用方显式传 `confirm=true`**：

```
apps/api/app/services/fin/evolution.py:1843  if not switches.evolution_enabled(): raise …
apps/api/app/services/fin/evolution.py:1845  switches.assert_hard_ok()      # 现在只剩实盘
apps/api/app/services/fin/evolution.py:1846  if not confirm: raise …        # ← 这道锁在
```

**结论：本段结束时，系统仍然不会自己生效任何东西。** 真正「自动」是 `L13` 才接上的。
证据见 §四.7（`test_apply_requires_explicit_confirm` 通过）。

### 2.2 `AUTO_APPLY_MESSAGE` 改「口径说明」，不再删也不再用作错误文案

旧常量是硬开关的错误文案（「必须为 0」）。移出名单后它不再是错误文案，但**没有删**——
改成「自动生效只对收紧方向放行」的**口径说明**，并接进 `switch_meta()` 的 `auto_apply.desc`。
理由：任务书 §三.B 要求「文案要说清只对收紧放行」，而界面口径现在就要对（哪怕纪律在 `L13` 才实现）。

### 2.3 `auto_apply()` 删除、改名 `ceiling_auto_apply()`（不留两个同名含义的函数）

旧的 `auto_apply()` 就是「读环境变量」，与新的 `ceiling_auto_apply()` 同义。留着会让
「天花板」与「生效值」两个概念在函数名上混淆，故**删除并改名**，调用点只有两处（`main.py` + `runtime_state`），
全仓无遗留调用（§六.5 grep 为证）。

### 2.4 迁移里**不改表名**（如实记在迁移注释里）

`fin_memory_switch` 现在装的不止「记忆」开关（`memory_enabled` / `evolution_mode` / `auto_apply`），
名字过时。**改名不是「加法」**（牵动读写点、缓存键、既有数据，有风险零收益），故保留原名，
在 `0055` 的表注释与正文里如实说明。

## 三、逐项改造

### A · 三个默认值改成「开」（`switches.py:66-69`）

```python
MEMORY_ENABLED_DEFAULT = "1"       # 0 → 1
EVOLUTION_MODE_DEFAULT = "paper"   # off → paper（依赖不齐仍会自动降 observe，逻辑没动）
AUTO_APPLY_DEFAULT     = "1"       # 0 → 1
LIVE_ORDER_DEFAULT     = "0"       # 保持 0（硬锁死，一字不动）
```

**非法值仍回落保守一侧**：非 0/1 → `0`；非 off/observe/paper → `off`；`FIN_AUTO_APPLY` 非法 → `0`。
「缺省 / 留空」用默认值（开），「值非法」才回落保守——两者分得清（有 `logger.warning` 留痕）。

同步改了 `.env.example`（`:352/358/361` 一带）、`.env.personal.example`（`:84/95/99` 一带）、
`docker-compose.yml` 的 api 段（`:215-218`）与 fin-worker 段（`:400-403`）的 `:-` 兜底默认值。

### B · `FIN_AUTO_APPLY` 从硬开关 → 真开关

1. **移出硬开关名单**：`HARD_SWITCH_KEYS` 只剩 `("live_order_enabled",)`。`hard_config_errors()`
   对实盘的行为一点没变。`SWITCH_KEYS` 加入 `auto_apply`。
2. **新增读取函数**：`ceiling_auto_apply()`（读环境变量）· `auto_apply_effective(project_id)`
   （天花板 ∩ 项目，取更保守）。
3. **按项目覆盖**：迁移 `0055` 加 `auto_apply BOOLEAN` 列 + 放宽流水账 CHECK。
4. **写入口**：`set_project_switch()` 支持 `auto_apply`（布尔校验、超天花板 400、写现值 + 追加流水；
   `live_order` 仍被 400 拦）。
5. **读覆盖**：`_read_override` 的 SELECT、`_jsonable_switch`、`selected_switch`、`can_change` 一并支持。
6. **展示与返回体**：`switch_meta()` 的「自动生效」从只读文字变成可改的真条目（带开/关标签、
   说明、「为什么灰」）；`runtime_state()` 的 `auto_apply` = **生效值**，`ceiling` / `selected` /
   `can_change` 三项都含 `auto_apply`（天花板 / 请求值 / 生效值齐了）。
