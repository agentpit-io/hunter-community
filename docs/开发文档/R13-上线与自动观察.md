### 1.2 行为逐字复用服务层（不重写判据）

观察的**唯一实现**仍是 api 的 `services/fin/evolution.py:observe_applied`（`R8` 交付）。工作流只做「到点、按市场、逐提案」地调用它：

- **越普通线**（提前停止线 / 观察期结束净收益 ≤ 失败线）→ **只写 `alert`**（`fin_alert_log` + 追加 `alert` 事件），**配置一动不动**，等人确认；
- **只有**踩到冻结计划的 `rollback_line` 才**自动回滚** —— 回滚目标取**版本链**（`applied` 事件的 `from_key`，再校验它仍在 `fin_param.strategies`、当前 active 正是那次生效的 `to_key`；核验不过 → 追加 `alert` + 拒绝，**不猜**）；
- 回滚一并产出三样：`rolled_back` 事件 · `fin_param_change_log` 行 · **一条 `polarity='refute'` 的失败经验**（写入失败**不许吞** → 落回灌重试队列，只读接口据此报「回灌待完成」）。

### 1.3 三条边界的落地方式

1. **单条提案观察失败不挂整条工作流**：`_observe_for_project` 逐提案 `try/except`，失败记进汇总（`observed=false` + `error`）继续下一个。
2. **回滚失败必须可见（红线 9）**：api 把「回滚核验失败」翻成 **409**、把「进化未启用 / 硬开关违规」翻成 **503**；工作流对这两类额外标 `rollback_error=true` 并打 **ERROR** 日志。用例 `test_rollback_failure_is_flagged_and_logged` 盯着。
3. **不碰数据库**：活动只经 `HunterApiClient` 走内网口令（`X-Hunter-Internal-Key`），`tests/test_no_ledger_access.py` 仍绿。

### 1.4 本机预跑（部署前的真跑，不是截图）

在**本机开发库**（`hunter`）先跑通整条链，确认接线无误再发版：

- 两个 R12 的「只选美股」项目各造一条 `passed → applied` 提案（构造影子样本 + 构造净值，见 §四.1 的口径说明）；
- 触发 `fin.observe` `US` → 项目 A `action=alert`（回撤 -8.5% 触及提前停止线，**配置不动**）、项目 B `action=rolled_back`（回撤 -15% ≤ 紧急线 -10%）；项目内其余 5 个无生效提案的项目 `proposals=[]`（**不是 `null`** —— CLI 的 proto 渲染把空数组显示成 `null`，SDK 取回是 `[]`，已核对）；

## 五、遗留问题与下一段

1. **观察期目前只看 `fin_valuation` 的模拟盘净值**：本部署的账本历史为空、快照价格窗口内不变，
