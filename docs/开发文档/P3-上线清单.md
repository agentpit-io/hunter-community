## 1 · 改 `.env`（**两行都要改**）

```diff
- HUNTER_VERSION=1.4.0
+ HUNTER_VERSION=1.5.0

- FIN_TAG=1.4.0
+ FIN_TAG=1.5.0
```

**为什么 `FIN_TAG` 也必须动**：本期 `paper`（`list_projects` 带出市场集合、市价单能力按表取）
与 `fin-worker`（`projects_for_market` 改成集合包含、港美股限价单定量）的代码都改了，
它们的镜像标签跟的是 `FIN_TAG`，不是 `HUNTER_VERSION`。
只改 `HUNTER_VERSION` 会让 api/web 升到 1.5.0、paper/fin-worker 停在 1.4.0 ——
**界面按已选市场出、执行却还按老口径过滤**，是最糟的一种不一致。

> 如果 `.env` 里这两行被注释掉了，不用加 —— `docker-compose.yml` 的默认值本期也已改成 `1.5.0`。
> 但**显式钉版本更好**（浮动标签会让下次升级悄悄漂）。

## 2 · 拉镜像 + 起服务

```bash
cd <仓库目录>
git fetch origin --prune && git pull --ff-only origin main

# 主站四个服务（本期 api / web 改了；llm-shim / opencode 也一并拉，保持版本一致）
docker compose pull postgres redis api web llm-shim opencode
docker compose up -d postgres redis api web llm-shim opencode
```

**如果演示站启用了智能交易（`fin` profile）**，再拉这两个（`FIN_TAG` 决定）：

```bash
docker compose --profile fin pull paper fin-worker temporal temporal-ui
docker compose --profile fin up -d paper fin-worker temporal temporal-ui
```

**顺序不要颠倒**：先 `postgres` 起好，再 `api` —— 迁移由 api 启动时跑，它需要库在线。

> `up -d` 会不会 Recreate？会（镜像变了必然 Recreate）。
> 这几个服务里 **只有 `postgres` 有状态且已挂具名卷**；api / web / llm-shim / opencode 都挂卷或本来无状态。
> **`opencode` 的会话正文在具名卷里**（一期事故后已修），Recreate 不丢。
> ⛔ **任何时候都不许 `docker compose down -v`**。

## 3 · 迁移 `0036` + `0037`（**自动执行**，只需确认）

迁移随 `api` 启动自动跑（`python -m app.migrate`，advisory lock 串行化）。
本轮新增的 `0036`（以及 P2 的 `0037`）**只做加法**：
`CREATE TABLE IF NOT EXISTS fin_project_market` / `ALTER TABLE … DROP NOT NULL`（只放松）/
按**已核实的事实**回填（现有项目 `market_scope='CN_A'`）；`0037` 只给 `fin_market_rule`
加一列 `market_order_supported`（非空默认 `false`，CN_A 回填 `true`）。
**可重复执行**，历史行一行未改。

### 怎么确认它跑了

```bash
docker compose logs api --since 10m | grep -E '迁移|migrate'
```

期望看到（数字以演示站实际为准，关键是 **`本次待执行 2 个`** 与 `0036` / `0037`）：

```
迁移 | ② 增量迁移（db/migrations）：共 38 个迁移文件，已应用 36 个，本次待执行 2 个
迁移 |   [1/2] 0036_project_markets.sql 完成
迁移 |   [2/2] 0037_market_order_supported.sql 完成
迁移 | ② 增量迁移完成：本次执行 2 个
```

**如果看到「迁移失败，api 不会启动」**：api 停在启动阶段（不会半死不活），
日志里给出文件名与行号；修好或回滚后再起。

### 直接查库确认（可选，最硬）

```bash
docker compose exec postgres psql -U hunter -d hunter -c \
  "SELECT market, currency, initial_capital FROM fin_project_market ORDER BY market LIMIT 5;"

docker compose exec postgres psql -U hunter -d hunter -c \
  "SELECT market, price_limit_mode, market_order_supported FROM fin_market_rule ORDER BY market;"
```

期望三行：`CN_A | pct | t`、`HK | none | f`、`US | none | f`。

**回填完整性**（`market_scope='CN_A'` 的项目必须每行都有市场行）：

```bash
docker compose exec postgres psql -U hunter -d hunter -c \
  "SELECT count(*) AS 缺市场行的CN_A项目 FROM fin_project p
    WHERE p.market_scope='CN_A'
      AND NOT EXISTS (SELECT 1 FROM fin_project_market m WHERE m.project_id=p.project_id);"
```
期望 **0**。⚠️ 若 >0，说明回填没跑完或有 `MULTI` 历史行 —— 迁移对「有 MULTI 行」的情形
只 `RAISE NOTICE`、**不编**（见 P1 报告 §2.3）。演示站现有 424 行项目全是 `CN_A`（0029 已核实），
本机复核不可达；若这条不为 0，**停下来人工核实**再用一次
`INSERT ... fin_project_market` 补，或按其语义「关停旧项目 + 开新项目」。

## 5 · 功能抽烟（四条，各 30 秒）

```bash
# ① 未登录也要能看市场状态（免登录前缀外的读接口在登录后调）
curl -s -H "Authorization: Bearer $TOKEN" localhost:8100/api/v1/fin/markets | head -c 600

# ② 当前项目带出市场集合（P1 落库、P3 界面依赖它）
curl -s -H "Authorization: Bearer $TOKEN" localhost:8100/api/v1/fin/projects/current | head -c 600
#   期望看到 "markets":[{"market":"…","currency":"…","initial_capital":…}]

# ③ 账户页的「市场与子账户」数据源（P3 新增字段）
curl -s -H "Authorization: Bearer $TOKEN" 'localhost:8100/api/v1/fin/account?market=HK' | head -c 900
#   期望有 "market_accounts":[…每个选中的市场一行，带 initial_capital 与 nav…]

# ④ 追加市场只增不减（把 <pid> 换成②里的 project_id；这条应回 400）
curl -s -o /dev/null -w '%{http_code}\n' -X POST \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"markets":["HK"]}' localhost:8100/api/v1/fin/projects/<pid>/markets
#   期望 400（隐含移除会被服务端拦下）—— 若回 200，说明「只增不减」没生效，别上线
```

浏览器打开 `https://hunter-community.agentpit.io/finance/setup`，**看四件事**：

1. 步骤条是 **7 步**（风险告知 → 选档位 → **选市场** → 板块偏好 → 策略选择 → 短线参数 → 确认开启）；
2. 「选市场」那一步三张卡片（A 股 / 港股 / 美股），各自写着本币 / 时区 / 交易时段 / 涨跌停模式 /
   T+N / 整手 / 手续费模型；**未选任何市场时「下一步」是灰的**；
3. 选上港股或美股，卡片下方**当场**出现「本版本对港美股不做价格带校验…」与「日历缺失该市场当日不可交易」；
4. 走到确认页，「已选市场 / 各市场本金」两行在，**不再出现「开户默认开设 A 股子账户」**。

> ⚠️ **演示站 `fin_market_calendar` 的 `CN_A` 仍为空**（HK/US 已于 2026-10-03 补种 669/730 行）。
> **只选 A 股的项目在演示站会因日历缺失而空跑** —— 这是**如实行为**，不是 bug。
> **上线验收要用「只选港股」或「只选美股」的项目**（`需求与实现方案.md` §4.5 / §7.8 的口径）。
