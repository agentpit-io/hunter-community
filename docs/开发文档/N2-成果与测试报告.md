## 〇、结论摘要

- **六条风控的规则逻辑一条没改**，改的只是参数来源：从「写死 A 股」改成
  读 `fin_market_rule` 的一行（时区 / 时段 / 可卖规则 / 手数 / 价格带模式 / 币种）。
  `engine.evaluate()` 拿不到市场规则行时**整笔拒绝**，不退回 A 股口径。
- **两个镜像装了 tzdata**，镜像内 `ZoneInfo('America/New_York')` / `Asia/Hong_Kong` /
  `Asia/Shanghai` 三地时区实测可取值（§三①）。
- **日历按 `(market, trade_date)` 读**；读不到该市场该日的日历行 → **判为不可交易**，
  并把原因写清楚（不许退化成「周一至周五即交易日」）。
- **港美股日历真建起来了**（拍板 §3.1 三步）：官方页结构化数据 → 人工种子兜底 → 对账。
  港股 669 行（`hkex_official`）、美股 730 行（`nyse_official`），

- 测试：paper `226 passed, 1 skipped`（N1 基线 `177 + 1`，**+49 条新用例，一条不减少**）；
  fin-worker `99 passed`（与 N1 逐项一致）；api fin 四件 `65` / 项目+报告 `32` / 迁移 `16` /
  market_scope `13`（**四组与 N1 数字逐项一致**）+ 新增 market_calendar `13`。

  因此当前 **HK / US 的委托会停在第 5 条（费用模型缺失）**。这不是本阶段的缺陷，

## 一、这一轮做了什么

### 1.1 镜像前置条件：装 tzdata（**先做**）

`apps/paper/Dockerfile`、`apps/fin-worker/Dockerfile` 的运行层 `apt-get install` 各加一个 `tzdata`：

```dockerfile
RUN apt-get update && apt-get install -y --no-install-recommends \
        curl ca-certificates tzdata \
    && rm -rf /var/lib/apt/lists/*
```

`risk/session.py` 原来硬编码 `CST = timezone(timedelta(hours=8))`，注释写明**根因就是 slim 镜像没有 tzdata**
（原 `:6-9`）。**没有**改成「把偏移写死在代码里」—— 那是把坑埋深。

### 1.2 统一时间工具（paper / fin-worker 各一份同实现）

新增 `apps/paper/app/market_time.py` 与 `apps/fin-worker/app/market_time.py`，
两份**逐字节相同**（两个服务的构建上下文互不可见，只能各留一份；`test_market_time_parity.py`
逐字节比对，漂了即红）。对外提供：

| 函数 | 作用 |
|---|---|
| `canonical_market(m)` | `a` / `cn` / `A` / `cn_a` → `CN_A`；不认识**抛错**（不猜） |
| `market_tz(m)` / `tz_name(m)` | IANA 时区对象 / 名字（`ZoneInfo`，进程内缓存） |
| `to_market(at, m)` | 任意时刻归一成该市场当地时间（naive 视为该市场本地时间） |
| `market_local_date(at, m)` | 该时刻在该市场当地是哪一天（**日历按它查**） |
| `market_of(code)` | 代码形态 → 市场（与 `fin_data.market_of` 同口径，单一实现） |

`snapshot/store._market_of` 改为**委托**给 `market_time.market_of`（只把 `CN_A` 折回旧标签 `A`），
不再另写一套判据。

## 二、偏离任务书 / 方案的决策与原因

> 无人值守模式（`拍板 §〇`）下遇岔路口按**最保守、最可核对**的选项继续，逐条标注。

1. **`apps/api` 也在本轮改了**（任务书正文只列了 paper 的六个文件）。
   原因：任务书 §3 明写「本阶段要把港美股日历真建起来（接口 → 人工录入 → 对账）」，
   而日历的**接口**在 `apps/api`（`internal_etl.py` 原来对 hk/us 直接 501）。
   **未改** `apps/api` 的报告 / 前端 / 调度（那是 N5 / N4）。

2. **印花税方向用新列表达**（而非「负费率 = 双边」这类约定）。`stamp_side` 是新加列，
   老行靠 `DEFAULT 'sell'` 行为不变。**没有**在代码里留「没有列就按双边」的推断。

3. **港美股费率不落数**（延续 N1 决策）：`fin_market_rule.fee_model_version` 对 HK/US 仍为 `NULL`。
   原因见 §五 —— 现有 `fin_fee_model` 的三个费用槽位**无法忠实表达**港美股费目结构
   （美股 SEC 规费 / TAF 是**按股 + 有上限**、且只对**卖出**收；港股结算费有 min/max），
   硬填一个百分数就是编数字。**本阶段只把「印花税方向」这一条参数化，不填费率数值。**

4. **`price_limit_mode='band'` 见到就拒绝**，不做半成品（`总控规则 §六.10`：灰色按钮会骗人）。

5. **本地 dev 的 `paper` / `fin-worker` 容器已重建**（`docker-compose.dev.yml` 的 `:dev` 镜像 +
   bind mount 的代码已开始依赖 tzdata，不重建就会运行期报错）。**未动** `api` 容器、
   **未动** compose 文件、**未** `down -v`。

6. **新建了三个临时库**（`n2_fresh` / `n2_clean` / `n2_final`）用于「干净库上的全量回归」，
   只 `CREATE DATABASE`，**未删任何库、未动 `hunter` 库的历史数据**。

## 五、遗留问题 / 交给 N3 的第一件事

1. **⚠️（最重要）港美股费率行仍未落表 → 当前 HK / US 委托停在第 5 条。**
   `fin_market_rule` 的 HK / US 行 `fee_model_version=NULL`，`fin_fee_model` 里没有 HK/US 行，
   所以 `check_fee_model(None)` 拒绝 → 实测回执 `failed_checks=["fee"]`（§三⑥）。
   **为什么不在本轮补**：现有 `fin_fee_model` 只有三个百分数槽位（佣金 / 印花税 / 过户费），
   而 **美股** SEC Section 31 规费与 FINRA TAF 是**按成交股数**计、**有上限**、**只对卖出**收；
   **港股**结算费有 min/max。硬塞一个百分数就是编数字（红线 §六.1）。
   **建议**：单独立一项，先扩 `fin_fee_model` 的表达力（按股费 + 上下限 + 方向），
   再按 SEC / HKEX 公布口径分年落行并标 `effective_from`。
   **这是 N5「港美股真下一单、真成交、真记账」验收之前必须消掉的项** —— 否则那一单走不通。

2. **半日市未落库**（见 §四）。要么扩日历写入（`sessions` 逐日覆写已支持），要么维持「放宽处理 + 留痕」。

3. **`fin_market_calendar` 的日中 `sessions` 优先**：N2 起 `session` 先用日历行的 `sessions`，
   为空才回落市场规则。若 N4 的调度要按半日市收窄时段，写进日历行即可生效。

4. **`apps/api` 报告 / 前端的时间口径**（`fin/report.py` 等 19 处 `CST`）留待 **N5**；
   行情侧的 `fin_data._market_tz()` 已是 `ZoneInfo`，无需改。

5. **本地 dev 的 `api` 容器镜像里 `/opt/hunter-migrations` 只到 `0028`**（N1/N2 的迁移是
   手工执行的）。演示站/CI 从仓库重建镜像时 `boot.sh → app.migrate` 会自动补齐；
   **本机 dev 的 `hunter` 库已手工补齐 `0029`–`0032`**。

6. **给 N3（行情与快照）的第一件事**：`Quote` 加 `market` 并把 `fin_snapshot.market` 写对
   （N1 已加列、`store.capture` 还没写它）；港美股报价的 `source` 名不符实
   （实际来自腾讯 `_free_quote`，却标 `official`，见 N0 报告 §九-4）一并改直。
