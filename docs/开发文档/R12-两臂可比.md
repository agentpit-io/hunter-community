### 1.1 新的定量口径（只接限价单的市场）

```
qty = min(档位手数, ⌊ 可用资金 × max_position_pct × 0.995 ÷ (参考价 × 每手股数) ⌋ × 每手股数)
```

- **可用资金** = 该市场子账户余额（真实）；**参考价** = 行情源当前报价（真实）；
  **每手股数** = `fin_instrument.lot_size`（真实）；**占比** = `fin_param.max_position_pct`（项目参数）。
  四个输入都是真的，没有一个是编的。
- `0.995` 是**买入手续费余量**（沿用 P2 的 `_CASH_CUSHION`，最贵的市场也只有它的几分之一）。
- **量价三输入（可用资金 / 参考价 / 每手股数）任一缺失 / 不可用 → 回落到档位固定手数** `cap`
  —— 拿不到可靠输入就不猜（与旧的「缺任一 → 出不了单」同一种「如实的不作为」精神，
  落点从「不出委托」换成「按档位固定手数出委托」，因为档位手数是配置里写死的数字、不是猜的）。
- 买不起一手（占比 × 可用资金买不到 1 手）→ `SampleNoBudget` → **本时点不出委托**（不编数量硬下单）。

### 1.2 为什么 A 股（市价单）路径**不**读占比参数（必答）

**市价单路径根本不取价格与可用余额** —— 一期口径：A 股出**市价单**，成交价由 `paper`
按对手价 + 滑点在执行那一刻决定，所以**出意图时不需要报价**（`activities.build_decision`
只在 `market_order_supported=False` 时才去取 `reference_price` / `lot_size` / `available_cash`，
见 `activities.py:409-420`）。

拿不到量价输入就不做占比定量 —— 硬按占比算，分母（参考价 × 每手股数）是**编的**。
这不是「漏读参数」，是**如实的不作为**：**有输入的路径才定量，没有输入的路径沿用档位固定手数**。

因此本阶段的验收**只用「只选美股」的项目**（对齐 `追加规则 §六.6` 与三期 `P4` 口径）——
A 股的市价单路径**一行未改**（`test_market_order_path_ignores_max_position_pct` 盯着：
占比从 0.9 掉到 0.1，委托数量仍是档位固定手数）。

### 1.3 策略读的字段 = 影子臂搬的字段（一处清单）

```python
# sample.py
STRATEGY_READ_FIELDS: tuple[str, ...] = ("max_position_pct",)

# shadow.py —— param_of() 从 STRATEGY_READ_FIELDS 推导，两处共用同一份
def param_of(config):
    cfg = config or {}
    return {name: cfg.get(name) for name in STRATEGY_READ_FIELDS}
```

少搬一个字段 = 影子臂读不到刚接上的参数 = 「接线做完了但 `delta` 还是 0」且**不报错**。
`test_shadow_flow.py::test_param_of_matches_strategy_read_fields` 断言两份清单**逐字相等**。

> `stop_loss_pct` / `take_profit_pct` / `hold_days_max` **本阶段不读**（§六「明确不做」）：
> 它们属于**持仓管理层**，示例策略是**只买不卖**的策略，在策略里自造卖出规则**那才是「编造」**。

## 二、偏离方案的决策与原因

| # | 事 | 决定 | 原因 |
|---|---|---|---|
| 1 | **`pct` 缺失时怎么办** | 沿用**旧口径**（不设占比上限、按可用资金定量），**不是**回落档位手数 | 任务书列的三个「任一缺失→回落」输入是**量价三输入**（可用资金 / 参考价 / 每手股数），`pct` 不在其中。量价输入都在、只是没配占比时，仍算得出真实数量 —— 回落档位手数反而会把一个能算的数换成写死的数。且这**逐位等于 R12 之前的旧行为**，无回归 |
| 2 | **`pct` 配了但形状不对** | 回落档位手数 | 「形状不对」= 拿不到可靠输入，与量价输入形状不对同处理 |
| 3 | **参考价缺失** | 直接 `SampleNoBudget`（不出委托），**不**回落档位手数 | 限价单**必须带价**：没有参考价就凑不出合法的限价委托（写 `limit_price=None` 会被 paper 风控拒）。「回落档位手数」只对**可用资金 / 每手股数**缺失生效（此时限价仍有参考价） |
| 4 | **`_position_qty` 用关键字参数** | 新签名 `(*, available, price, lot, cap, pct)` | 三个以上位置参数、类型又都是 `Any`，位置调用极易传错；关键字强制调用方写清 |
| 5 | **`data_snapshot` 记 `params_used`** | 记策略**真正读了**的字段（由 `STRATEGY_READ_FIELDS` 推导），`max_positions` 不再记 | 旧代码把 `max_position_pct` / `max_positions` 当「留痕」写着（注释原话「策略未来读档位参数时用它」）。现在 `max_position_pct` **参与定量**了，留痕应与实际读取一致；`max_positions` 策略不读，不再写（全仓无读取方） |
| 6 | **验收项目用 `store.create_project` 建** | 调**真实服务函数**建「只选美股」项目，**不手写 SQL** | 与「唯一入口」同一纪律；`store.create_project` 是向导第六步走的同一条路（含账户 / 项目 / 市场 / 参数四张表） |

## 三、`delta` 的量级：为什么它很小、为什么它可解释

影子跑用的是**当天收盘那一张真实快照**（`paper.snapshot.capture`，`quote_as_of` 恒定），
窗口内**价格不变**。于是：

```
组合净值 = 现金 + 持股市值 = 本金 − 累计手续费        （买入价 = 估值价 ⇒ 无价差损益）
delta    = 候选净值 − 现行净值 = 现行累计手续费 − 候选累计手续费
```

**即：同价快照下，两臂组合净收益的差**只可能**来自手续费**。这不是「没能分叉」——
分叉的证据是**委托数量 447 vs 149**（见 §四.1）；`delta` 是这两条数量轨迹**自然产生**的账面结果。

`R12` 的验收**不要求结论是 `passed`**（§三红线），只要求 **`delta` 非零且可解释**。
若窗口内有真实价差，`delta` 会大得多；本部署的快照是收盘价、窗口内不变，所以**如实偏小**——
这是口径使然，**不是我们挑的**，也不拿价格动不了的窗口去硬凑一个漂亮的数（红线 13）。

### 4.1 两臂真的分叉（验收 §①）—— 同一 `validation_id`、同一时点，`signal` 不同

**案例 B**（`evp_fda3a842245b42f48b1c14e3`，2026-09-01 `US-0930`）：

```
    arm    | trade_date |  point  |      quote_as_of       | qty | price_type | limit_price | filled
-----------+------------+---------+------------------------+-----+------------+-------------+--------
 candidate | 2026-09-01 | US-0930 | 2026-10-02 20:00:01+00 | 149 | limit      | 333.69      | t
 incumbent | 2026-09-01 | US-0930 | 2026-10-02 20:00:01+00 | 447 | limit      | 333.69      | t
```

两臂 `price_type` / `limit_price`（真实参考价）**相同**，**只有 `qty` 不同**：
`1,000,000 × 0.15 × 0.995 ÷ 333.69 = 447`（现行）对 `1,000,000 × 0.05 × 0.995 ÷ 333.69 = 149`（候选）。
**案例 A** 同理：首日 `74`（0.25）对 `44`（0.15）。

### 4.2 `delta` 非零 + 判定结论（验收 §②）

**案例 B · `shadow_metrics()` 真实输出**（样本足够、窗口已结束）：

```
initial_capital = 1000000     comparable_samples = 23
incumbent: final_total_assets=999902.5293  net_return=-9.74707e-05  trades=23  cost=97.4707
candidate: final_total_assets=999931.1598  net_return=-6.88402e-05  trades=23  cost=68.8402
delta_candidate_minus_incumbent = 2.86305e-05      （= (97.4707 − 68.8402) ÷ 1,000,000）
事件链：created → validating → inconclusive
verdict = inconclusive
reason  = 窗口已结束但差异 +0.0029% 落在 [-0.01, 0.01] 之间，或样本质量不足以支撑结论
```

**结论是 `inconclusive`，不是 `passed`、也不是 `failed`**，为什么：
- **不是 `passed`**：`+0.0029% < pass_line(+1%)` —— 差异没到通过线。
- **不是 `failed`**：`+0.0029% > fail_line(−1%)`，候选最大回撤 `-0.64bp` 也没触及提前停止线（`-8%`）。
- **样本与窗口都够**（23 ≥ 20、22 ≥ 20 交易日），所以这次 `inconclusive` 是**「差异落在中间带」**，
  不是「样本不足」。**这是真实结论，我们没挑好看的**。

`delta` **完全可解释**：候选单票占比更小 → 每步买入金额更小 → 累计手续费更少（68.84 对 97.47）
→ 组合净收益更高，于是 `delta` 为正。**逐位自洽**：`delta × 本金 = 28.63 = 手续费差`。

**案例 A**（`manage`·100k，`0.25 → 0.15`）：`delta = +2.338e-06`，**18** 个可比样本 →
`inconclusive`（`可比样本 18 < 最小可比样本 20`）。现行臂每步买 74 股、第 19 天起买不起一手而停手，
候选臂买 44 股、23 天全程在买 —— 两臂**现金轨迹**也因此不同（现行 `final=99990.1227`、候选 `99990.3565`）。

## 五、遗留问题与下一阶段（`R13`）交接

1. **`delta` 的量级受「快照价格恒定」约束**（§三）：本部署影子用当日收盘快照，窗口内无价差 →
   `delta` 只来自手续费。要看到更大的 `delta`，得让窗口跨真实价差（影子每晚跑、快照逐日变）
   或给影子补一条按历史日线重放的口径 —— 那是另一件事，**本轮不改影子口径**。
2. **`inconclusive` 是当前的主结论，`passed` 仍未出现**：真实样本（每晚影子积累）足够后，
   才会自然走到 `passed`/`failed`。**不许**为了出 `passed` 放宽 `pass_line` / `min_comparable_sample`（红线 10/13）。
3. **A 股路径仍不读占比**（§1.2）：要 A 股也按占比定量，得先让市价单路径拿到价格与余额
   （一期口径是「不取」，改了要重跑 A 股回归 `scripts/regress_a_backtest.py --compare`）。**本轮没做**。
4. **两个验收用项目 / 提案留在本机开发库**（`prj_a09d23aa686a4bd48dd4e38d` · `prj_b6a0b6e3326a4210908f5e98`
   及其 `inconclusive` 提案），供 `R13` 出口复用与回看；**没有部署演示站**（§六）。
5. **`R13`（自动盯盘 + 出口）**：`fin.observe` 接调度 → 观察期自动检查 / 越线告警 / 紧急回滚。
   本轮 `delta` 已非零且真实，`R13` 的观察对象（生效后的表现）**第一次有了真实的影子成绩可比**。
