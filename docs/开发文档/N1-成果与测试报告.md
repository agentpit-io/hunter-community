## 一、这一轮做了什么

### 1.1 迁移 `0029_market_scope.sql`（167 行）—— 打开市场维度

| 表 | 改动 | 现状回填 |
|---|---|---|
| `fin_project` | `currency` CHECK → `IN ('CNY','HKD','USD')`；`market_scope` CHECK → `IN ('CN_A','HK','US','MULTI')` | 无需回填（424 行本就 CN¥/CN_A） |
| `fin_account` | 同上补 CHECK；**新增 `market` 列**（`NOT NULL DEFAULT 'CN_A'` + CHECK） | 3 行回填 `market='CN_A'` |
| `fin_instrument` | `exchange` CHECK 放开加 `HKEX/NASDAQ/NYSE/AMEX/CBOE`；`board` 放开加 `hk_main/hk_gem/us_main/us_other`；**新增 `market`、`currency`**；`limit_up_pct`/`limit_down_pct` 放开 NOT NULL | 15 行回填 `CN_A`/`CNY` |
| `fin_market_calendar` | **新增 `market`、`calendar_source`、`fetched_at`**；**主键 `trade_date` → `(market, trade_date)`** | 435 行回填 `market='CN_A'`、`calendar_source='akshare'` |

| `fin_fee_model` | **新增 `market`、`currency`** | 1 行回填 `CN_A`/`CNY` |

### 1.2 迁移 `0030_market_rule.sql`（115 行）—— 新增市场规则表（**本期核心**）

字段**照设计文档 §4.1 一张不省**：`market / currency / timezone / sessions / points /
sellable_rule / sellable_days / lot_rule / lot_fixed / price_limit_mode / fee_model_version /
source / effective_from / updated_at`。三行种子与来源见 §三 证据。

### 1.3 迁移 `0031_ledger_currency.sql`（70 行）—— 账本加币种

`fin_order` / `fin_trade` / `fin_cash_ledger` / `fin_position` / `fin_valuation` 各加
`currency TEXT NOT NULL DEFAULT 'CNY'`（+ CHECK 三币种），历史行回填 `'CNY'`。
**不加 `fx_rate`**（汇率只在汇总处现取，设计文档 §3.1 A 方案）。

### 1.4 追加：主键变更的**依赖 SQL 同步**（2 处，机械改动）

`fin_market_calendar` 主键变成 `(market, trade_date)` 后，原来按单列 `trade_date` 的
`ON CONFLICT` **会运行时报错**（`no unique or exclusion constraint matching ...`）。
必须同步的只有两处，且都是**把冲突目标换成新主键**、行为不变：

- `apps/paper/app/routers/reference.py` 的 `upsert_calendar`（A 股日历写入路径）；
- `apps/paper/tests/helpers.py` 的日历夹具。

已实测：paper 起新代码后 `PUT /api/v1/market-calendar/{d}` **HTTP 200**、连打两遍幂等、
落库行 `market='CN_A'`（见 §三）。

## 二、偏离任务书 / 方案的决策与原因

> 无人值守模式（`拍板 §〇`）下遇岔路口按**最保守、最可核对**的选项继续，逐条标注。

1. **放宽了 `fin_instrument.limit_up_pct` / `limit_down_pct` 的 `NOT NULL`。**
   任务书对 `fin_instrument` 只写了「CHECK 放开 + 新增 market/currency」，没提这两列。
   但港美股**没有每日涨跌幅限制**（N0 报告 S6、拍板 §四 `price_limit_mode='none'`），
   要让退出标准 ③「能插入港美股标的」成立且**不编一个假幅度**，只能把这两列放开为可空、
   港美股存 `NULL`（「空的比假的好」）。A 股 15 行原值原样保留，语义未变。
   **N2 实现风控第 4 条时按 `price_limit_mode` 决定是否读这两列。**

2. **未动 `fin_account` 的 `fin_account_one_per_user` 唯一索引。**
   任务书说「让『项目 : 市场子账户』变成一挂多（**新增 `market` 列**）」——
   括号已把落地方式写成「加列」。真正放开「一个用户多个市场子账户」（去唯一索引 +
   开户流程）属 **N4（调度与账本）**。本期**只做加法**，不动索引（动它是删结构，超出本轮）。

3. **港美股费率不落数：`fee_model_version = NULL`，`source` 写 `unavailable`。**
   费率随年份变（美股 SEC 规费每年调），必须按公布口径分年落 `fin_fee_model` 并标 `effective_from`。
   本期**不填一个看起来合理的数**（红线 §六.1）。

4. **港美股 `points`（调度时点）标为「本项目自定」。**
   时点是**我们自己的调度配置**，不是交易所公布的规则。三条 `source` 里逐条写明
   「调度时点=本项目自定（结构对齐 A 股六时点，见 `points.py`）」，**没有冒充交易所来源**。
   N4 建每市场 Schedule 时可再调。

5. **`fin_instrument` 的 `board` 枚举用了 A 股没有的 `hk_gem` / `us_other`。**
   港交所公开有主板（Main Board）与 GEM 两个板；美股没有与 A 股对应的分层，
   `us_other` 是给非主板/OTC 留的分档。**枚举放宽只加值，不删旧值**，A 股四个值一字不变。

6. **本机 `paper` 容器已 `restart`**（不改 compose、不 recreate、不 build）。
   `apps/paper/app` 是 bind mount，文件改动即时可见，但**已在内存里的 Python 模块不会重载**——
   不重启则运行中的 paper 仍用旧的 `ON CONFLICT (trade_date)`。paper 无状态卷，`restart` 安全。
   **部署到演示站时（N5），新镜像自会带上这次代码。**

## 五、遗留问题 / 交给 N2 的第一件事

1. **`paper` 的日历读取路径仍未带市场过滤**（`ledger.py` / `reference.py` 的
   `WHERE trade_date = %s`）。当前库里只有 `CN_A` 行故正确；**N2 加港美股日历种子后必须
   改成 `WHERE market = %s AND trade_date = %s`**，否则同日多市场会取到任意一行。
2. **`fin_instrument.limit_up_pct/limit_down_pct` 现可为 NULL**（港美股）。
   N2 的风控第 4 条（价格限制）**必须按 `fin_market_rule.price_limit_mode` 决定读不读**，
   不能对 NULL 做算术。
3. **`fin_market_rule` 的 `sessions`/`points` 值**要接到 `paper/risk/session.py`
   （现在仍硬编码 `CST=+8`）与 `fin-worker/app/points.py`（现在只有 A 股一套六时点）。
4. **`fin_account.market` 已加但唯一索引未动**（见 §二.2）；多市场子账户开户属 N4。
5. **`fin_market_calendar.calendar_source` / `fetched_at` 目前为空**（新种子由写入方填，
   历史 A 股行已回填 `'akshare'`）——N2 的港美股种子写 `hkex_official` / `nyse_official`。
