## 六、就地修的问题（**每一处「改了什么 / 怎么验 / 结果」**）

### 6.1 代码缺陷 · A 股「费用」卡片显示的是**美股费率**

- **现象**：`GET /v1/fin/markets` 里 CN_A 的 `constraints[key=fee].text`
  = 佣金万分之1 / 卖出印花税 — / 过户费万分之0.2（**美股费率**），`source=fin_fee_model:fee-us-v1`；
  而 CN_A 的 `rule.fee_model_version` 明明是 `fee-cn-a-v1`。**用户看到的是编的 A 股费率。**
- **根因（两条叠加）**：
  1. `apps/api/app/services/fin/views.py::_fee_model` 按市场查不到行时**无条件回落**
     「`ORDER BY version DESC LIMIT 1`」——`fee-us-v1` > `fee-hk-v1`（字典序），取到美股行当 A 股费率。
  2. **全仓没有任何迁移幂等写入 `fee-cn-a-v1`**（`0029` 假定它已由一期落表、`0034` 只补了 HK/US）
     → 从迁移建起来的库（演示站就是）`fin_fee_model` **只有 HK/US 两行**。
- **怎么修**：
  - 代码：`_fee_model` 改成**只有老库（没有 `market` 列）才回落**；列在、行缺 → 返回 `None`；
    `constraints()` 对该情形渲染「该市场的费率行尚未配置」的降级文案（**不显示任何数字**）。
  - 数据：新增幂等迁移 `db/migrations/0038_fee_model_cn_a.sql`，写入一期的 `fee-cn-a-v1`。
- **怎么验**：
  - 单测：`apps/api/tests/test_fin_markets_rule_view.py` +2 条
    （① A 股费用卡片必须引 `fee-cn-a-v1` 且是 A 股费率形状；② **删掉该行后 `_fee_model` 返回 `None`**）。
  - 跑：`api`（`test_fin_markets_rule_view.py`）**11 passed**。
  - 演示站：升 `1.5.1` 后 `0038` 真实执行 → `fin_fee_model` 三行齐 → `/v1/fin/markets` 的
    CN_A `fee.source` = **`fin_fee_model:fee-cn-a-v1`** ✓。
- **tag**：`v1.5.1`（新 tag，未移动 `v1.5.0`）。

### 6.2 代码缺陷 · 港股「收市竞价」时段在兜底里缺失

- **现象**：港股时点被驱动时，`16:08`（收市竞价那根 tick）的报价被判「不在交易时段内」→ 委托被拒。
- **根因**：`apps/fin-worker/app/activities.py` 的 `DEFAULT_SESSIONS["HK"]` = 两段
  （`09:30-12:00` / `13:00-16:00`），而 `fin_market_rule.sessions` = 三段（**多 `16:00-16:10`**）。
  `_market_sessions` 优先读规则、读不到才用兜底 —— 凡「读规则失败」那次日历同步写出来的行，
  都会把收市竞价判成不在时段。**同一事实写两处、漂了**（本仓反复出现的那类）。
- **怎么修**：把 `DEFAULT_SESSIONS["HK"]` 补齐 `{"open":"16:00","close":"16:10"}` 并写清为什么。
- **怎么验**：演示站 `fin-worker` 容器内直接读常量
  `HK fallback: [{'09:30','12:00'},{'13:00','16:00'},{'16:00','16:10'}]` ✓；
  数据侧（演示站日历）已由一次真实的 `HK-0915` preopen 同步改正，`00700` 随后在该 tick 上**成交**。
- **tag**：`v1.5.1`。

### 6.3 环境（演示站库）· 三处数据缺口

**这三处都是「演示站环境/数据」，按 P4 §6 就地修**；其中「HK 时段」的**根因是代码**，

### 6.4 单列一处**不是问题**、但要说清的：闭市时段成不了交

只能临时放宽新鲜度阈值（§五.3 第 3 条）—— 已改回，交易日不需要。

## 九、遗留问题 / 交接

1. **闭市时段无法成交（设计如此）**：快照 `quality/missing_flag` 是**首次 capture 时算、只追加**。
   同一根 tick 一旦被「过期时」首采，就**永久 stale**。要不要让「同一 `snapshot_id` 在新鲜期被再采到时
   允许提升 `quality`」，是**口径决定**，本轮没动（改它要重跑估值/对账的回归）。
2. **演示站账本基本是空的**（`fin_order/instrument/report/valuation` 起了个初始值，`fin_account` 1 行）。
   `P3-上线清单`/`P4.md` 里的「424 行项目」**是错的**，已在 §1.4 如实记。**只选 A 股的项目在演示站仍会因
   `CN_A` 日历为空而空跑**（HK/US 已补种）—— 验收要用只选港/美股的项目。
3. **`fin_report.market='MULTI'` 会给只选港股的项目也生成一份**（N5 既有行为，P3 已在界面侧处理：
   只在已选 ≥2 时展示）。本轮未动。
4. **本轮为演示成交临时放宽过 `PAPER_SNAPSHOT_STALE_SECONDS`**（已改回 900）。
   交易日验收不需要这一步；记录在案，免得后来人以为是默认口径。
5. **`test_api.py` 的两条内部键用例在一次性容器里失败**（既有环境性问题，非本轮引入）——
   若要让一次性容器也能跑绿，得处理「config 早于 conftest 读 env」的导入顺序。
6. **P2 的遗留仍在**：港美股费率仍是回测级近似（`fee-hk-v1`/`fee-us-v1` 的 `note` 写明）；`list_projects` 的 `LIMIT 500`。
