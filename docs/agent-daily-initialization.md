# 小鹿首次日线初始化与调度（2026-10-09）

## 原因

SaaS策略中心迁移只建了rs_daily表，未导入全市场历史；悬停图表按需取个股日线，并不写入此表，因此图表正常不等于小鹿可运行。部署只数17张表不足以验收小鹿。

## 修复约定

- 部署验收必须确认美股基准 __BENCH__ 和真实个股历史均存在，不能用少数自选股冒充整市场数据。
- SaaS首次安装可运行 api/scripts/bootstrap_agent_daily.py。它只初始化空的美股rs_daily，从现有行情中台只读获取最多320根，按当前RS排名池匹配；缺失或尾日滞后的股票复用原腾讯取数、限速、熔断。最新交易日覆盖需达到原90%阈值，整市场单事务写入，禁止覆盖已有历史，失败整体回滚。
- 基准取原腾讯标普500通道，OHLCV不填造值，不复制agent_day、交易、持仓、用户策略或旧研究状态。为什么：旧账本属于旧回测口径，不能当成本次SaaS运行结果。
- 首次初始化脚本是SaaS中台适配，不给开源版引入私有数据库依赖；开源版仍用自己的rs_history下载流程。两仓共享的空缓存和时区修复保持一致。
- 全部quant CronTrigger显式指定Asia/Shanghai。为什么：CronTrigger对象单独构造时可能取UTC宿主机时区，调度器声明上海时区也不能修正已构造的trigger，06:30会误排到北京时间14:30。
- screen_asof不缓存基准为空的store。为什么：否则写库后仍需等20分钟才能运行。

## 验证

UTC宿主机调度回归、空库转为有日线后的缓存回归、真实OHLCV转换和缺值拒绝回归已覆盖。初始化前必须dry-run核对最新覆盖率，初始化后检查rs_daily行数/交易日，再触发真实run_latest并核对数据库账本及dashboard。接口200不能替代真实运行。
