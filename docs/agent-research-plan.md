## 方案

1. **页面**:不为每个新策略新做页面。`agent.html` 顶上加分页「研究台 / 运行看板」。
   研究台 = 按阶段(立项 → 全年回测 → 纸上跑 → 封存)的看板 + 同口径对照表 + 净值叠加图;
   点进任一研究线打开的就是现有看板,只多一行面包屑(`?line=vcp&branch=c`)。
   **不另起页面的理由**:每页重做十几个区块、重接数据、重写自检,而且手续费 / 胜率计数 / 回撤口径会分叉,
   最后数字互相不可比 —— 研究要的恰恰是可比。
2. **保留 VCP = 封存,不删不停**,做三件事,各防一种丢法:
   - 冻结优化器(`agent_opt.step` 跳过封存线,`run_day` 照跑)—— 防对照组自己换了参数
   - git 打标签 `vcp-archive-v3` + F 盘整仓备份 —— 防改公共模块时顺手改了 VCP 行为
   - 按方向导出成交 / 持仓 / 净值 / 版本 + 历史交易记录 CSV —— 防误跑 `agent_run reset`
3. **后端**:在现有「方向 BRANCHES → 引擎 ENGINES → 池 POOL」上面加一层「研究线」分组 `LINES`
   (名称、状态、下属方向、假设、淘汰线、对照组,存 `agent_meta`)。
   VCP 的四个方向键原样不动,**零数据迁移**;新方向用全局唯一键(如 `donchian`)。
   新接口 `GET/POST /api/quant/agent/research`,对照数字复用 `_branch_summary`。
4. **研究流程**(硬门槛):立项(淘汰线提交即锁定,防看过结果再改)→ 全年回测(期望 > 0 且回撤 ≤ 对照组 1.5 倍)
   → 纸上跑 → **满 30 笔**判定(期望 < 0R 或超额不如 VCP 封存版 → 淘汰,数据保留)→ 晋级或封存。
