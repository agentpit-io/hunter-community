> `SKILL.md` 第 3 步「报告组装」引用的就是这份文件。
> M1 之前它**不存在**，模型照着找会扑空（待办池 P1-14），M5 补上。
>
> 这是**结构**模板，不是话术模板。每一格都必须由本次工具返回填充；
> 填不了就写「本次未取到」并说明是哪个工具、什么原因 —— 不许留空，
> 更不许用"行业一般水平""根据历史推测"之类的话把空缺补上。

## 报告骨架

### 一、一句话结论

一句描述性的话，说清「这家公司现在处在什么状态」。
**不给买卖指令**（不写"建议买入/卖出/加仓/减仓/目标价"），
写"当前估值处于近五年 XX% 分位，盈利增速 XX%，主要不确定性在 XX"这样的陈述。

### 二、关键数字表

| 指标 | 数值 | 口径 / 期间 | 来源工具 |
|---|---|---|---|
| 现价 | | | |
| 市盈率 TTM | | | |
| 市净率 | | | |
| 近一期营收 / 同比 | | | |
| 近一期归母净利润 / 同比 | | | |
| 毛利率 / 净利率 | | | |
| ROE | | | |
| 资产负债率 | | | |
| 52 周区间与当前分位 | | | |

**每一行的"来源工具"列必填**，写成 `mcp__uzi__stock_deep_analysis` /
`mcp__akshare__akshare_call(stock_financial_analysis_indicator)` 这样能追回去的形式。
取不到的行写 `—（<工具名> 本次未返回该字段）`。

### 三、投资论点（正面）

3–5 条。每条的格式固定：

- **论点**：一句话。
- **支撑数据**：具体数字 + 口径 + 来源工具。
- **这条论点的前提**：什么情况下它不成立。

没有数据支撑的"论点"不要写。

### 四、风险点

3–5 条，与第三节同样的三段式（论点 / 数据 / 前提）。
**风险点不许省略**——只写好处的报告是不合格的。
如果本次数据里确实没看到明显风险信号，就写明
「本次取到的数据中未出现 XX 类信号，但这不等于没有风险，未覆盖的维度是 ……」。

### 五、估值区间

- 用了哪种方法（相对估值 / 历史分位 / 绝对估值），**方法必须写出来**。
- 输入了哪些数字，各自来自哪个工具。
- 得到的区间，以及这个区间对哪些假设最敏感。
- 如果本次数据不足以给出区间，**直接说给不出**，并说明缺哪些输入。
  给不出区间不是失败，编一个区间才是。

### 六、数据完整性说明

必写的一节，列清楚：

- 本次实际调用了哪些工具、各自返回了什么。
- 哪些工具失败了 / 返回为空，原因是什么。
- **有没有返回被裁剪**：看到 `_hca_size_guard`、`truncated: true` 或
  `[atomcode: output truncated …]` 就在这里写明「XX 工具只取到前 N 条（共 M 条）」。
  被裁掉那段里的数字不许出现在前面任何一节。

### 七、AI 生成标识与风险提示

按工作区 `.atomcode.md` 第 6.4 节的要求写，不要改措辞。

## 三条硬约束（与 `.atomcode.md` 一致，这里再点一遍）

1. **一个数字都不许编。** 表里每个数都要能追到某次工具返回。
2. **不给买卖指令。** 用描述性语言陈述状态与不确定性。
3. **缺就是缺。** 写"本次未取到"比填一个像样的数字好得多。
