# UZI · 分部建模

## 什么时候用

公司有**两块以上业务、增速与利润率差异明显**时。典型信号:

- 用户问「哪块业务在赚钱」「新业务能不能撑起估值」
- 整体增速平淡,但市场给了高估值 —— 通常是在为某一块业务定价
- 传统业务在衰退、新业务在起量,用整体口径会把两件事抹平

**不适用**:单一业务公司。硬拆只会制造精度幻觉,直接说明"该公司业务单一,
分部建模无增量信息",改用整体 DCF。

## 怎么做

### 第 1 步 · 拿分部数据

调 `uzi_stock_deep_analysis` 取财务;分部数据通常在**年报/半年报正文**里
(`a.announce`),不在标准财务接口中。

**拿不到分部数据就停**。这时只有两个诚实的选择:
1. 说明"该公司未披露分部数据,无法做分部建模"
2. 若能从公开信息估算,**明确标注哪些是估算的、置信度如何**

绝不能凭印象拆分部收入 —— 拆出来的每个数字都会被当成披露值看待。

### 第 2 步 · 分部现状表

```
分部      收入   占比   YoY   毛利率   毛利占比
主业A     xx亿   60%    +5%    35%      52%
新业务B   xx亿   25%    +80%   45%      28%
其他      xx亿   15%    -10%   20%      20%
```

**毛利占比往往比收入占比更能说明问题** —— 一块 25% 收入贡献 40% 毛利的
业务,才是真正的价值中枢。

### 第 3 步 · 逐分部预测

每块业务分开预测,**驱动因子不能一样**:

- 成熟主业:量价拆分,增速向行业增速收敛
- 高增新业务:渗透率/市占率驱动,给出天花板假设
- 衰退业务:诚实地给负增长,不要用"企稳"回避

每个分部写清:**核心驱动因子是什么、如果它错了收入差多少**。

### 第 4 步 · 分部估值(SOTP)

不同业务给不同倍数 —— 这是分部建模的核心价值:

```
分部A   EBITDA xx亿 × 12x  = xxx亿   (成熟制造,同业中位)
分部B   收入   xx亿 × 8x   = xxx亿   (高增 SaaS,参照可比)
分部C                       = xxx亿
────────────────────────────────────
合计企业价值                  xxx亿
− 净负债                      xx亿
= 股权价值                    xxx亿   对应 x.x 元/股
```

**每个倍数写明参照对象。**「给 8 倍 PS」是空话,
「参照 A/B/C 三家同类可比公司 6-10x 中枢」才成立。

### 第 5 步 · 敏感度与结论

回答这两个问题:

1. **哪一块分部对整体估值影响最大?** 给出"该分部估值 ±20% 时整体变化多少"
2. **市场当前定价隐含了什么?** 用当前市值倒推:
   若主业按同业倍数只值 X 亿,那么剩下的 (市值−X) 就是市场给新业务的定价——
   这个数字合理吗?

第 2 问常常是整份分析里最有价值的一句话。

## 硬性要求

1. **分部数据必须来自披露**。估算的要标注,不许混在一起
2. 每个分部的倍数写明参照对象与区间
3. 各分部相加后**要减净负债**,别忘了
4. 结论落在「市场隐含定价是否合理」,而不是一个 SOTP 总数

- `uzi_stock_deep_analysis` — 取财务、公告
