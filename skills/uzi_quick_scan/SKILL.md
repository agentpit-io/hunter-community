# UZI · 速判

## 什么时候用

盘中要快、或者初筛一批票时。用户要的是**一个结论加一句理由**,
不是一份报告。

**克制是这个 SKILL 的核心。** 拿到深度分析的一大堆数据后,
最大的诱惑是全倒出来 —— 那样就变成了「深度分析」,速判就没有存在意义了。

## 怎么做

### 标准模式

调 `uzi_stock_deep_analysis`,然后**只输出这些**:

```
{名称} {代码}    现价 xx.xx  ({+N%})

结论    买入 / 持有 / 卖出 / 观望
理由    一句话 —— 必须带一个具体数字
关注    一件事 —— 接下来最该盯什么
风险    一句话 —— 最大的那个
```

四行,不要第五行。

**理由必须带数字。**「基本面稳健」是废话,
「近三季营收增速 22%/25%/24%,现金流同步」才是理由。

### 带评委投票模式

用户说「带评委投票」「专家怎么看」时,追加一段:

```
买入 N 票 · 持有 N 票 · 卖出 N 票    共识度 N%

多数派理由    一句话
少数派理由    一句话 ← **这条往往更值钱**
```

**少数派意见必须给。** 一致同意的时候通常是共识已充分定价、
上行空间有限;分歧大反而说明有认知差。共识度高本身要提示。

## 什么时候拒绝给结论

以下三种情况,**不要硬给买卖结论**,直接说明:

1. **关键数据缺失** — 拿不到财务或行情,就说"数据不足以速判"
2. **消息面剧烈变动中** — 刚出重大公告、停牌、被立案,速判没有意义
3. **用户问的是自己不熟的票且金额很大** — 建议走完整深度分析

速判的价值在于快,不在于**任何情况下都给个答案**。

## 硬性要求

1. **四行结构,不许扩写**。要详细请用深度分析
2. 理由必须带具体数字
3. **绝不编数据**。拿不到就说"数据不足以速判",这是合法输出
4. 带评委投票时**必须给少数派意见**
5. 结论用"买入/持有/卖出/观望",不用"可以考虑""建议关注"这类不承担的措辞

## 需要的工具

- `uzi_stock_deep_analysis` — 取行情、财务、新闻
