# UZI · 组合调仓

## 什么时候用

用户问「怎么调仓」「仓位合不合理」「该减谁加谁」。

## 前提检查(先做,别急着给建议)

三件事没有就问,**不要替用户假设**:

1. **持仓明细** — 没有就提示先录入,不要凭空举例
2. **目标配置** — 用户想要什么样的组合?没说过就先问,
   或用他的风险画像(`risk_profile` 记过的)推断,**并说明你在用它**
3. **约束** — 单票上限、现金比例、不能碰的标的

## 怎么做

### 第 1 步 · 漂移诊断

```
标的      当前权重   目标权重   漂移    金额
600xxx     28%        20%       +8%    +xx 元   ← 超配
000xxx      5%        15%      -10%    -xx 元   ← 低配
现金       12%        10%       +2%
```

先说清楚**漂移是怎么来的**:是涨出来的(赢家变重)还是买出来的。
前者是自然现象,后者说明执行偏离了计划 —— 处理方式不同。

### 第 2 步 · 交易清单

```
动作   标的     数量      金额     理由
减持   600xxx   xx 股    xx 元    超配 8%,回到目标
增持   000xxx   xx 股    xx 元    低配 10%
```

**每笔都要有理由,而且理由不能只是"回到目标权重"** ——
要说清为什么这个目标权重是对的。

### 第 3 步 · 成本测算(这一步最容易被跳过)

A股实际成本:

```
卖出印花税    成交额 × 0.05%(单边收,只卖出时收)
佣金          双边 · 万分之 2.5 左右 · 最低 5 元/笔
过户费        沪市 成交额 × 0.001%
冲击成本      小盘股/大额单要额外考虑
────────────────────────────────
总换手成本    xx 元 = 组合市值的 N%
```

然后回答关键问题:**这次调仓值不值得?**

> 换手成本 0.35%,而漂移带来的风险改善有限 —— 建议**不调**,
> 等漂移超过 10% 再动。

**"建议不调"是完全合法的结论,而且经常是对的。** 频繁再平衡的成本
会吃掉大部分收益,这一点必须敢说。

### 第 4 步 · 执行提示

- 分批还是一次?流动性差的标的要分批
- 有没有临近的事件(财报、解禁)值得避开
- 税务:A股无资本利得税,但持有不满 1 个月的股息税率更高

## 硬性要求

1. **没有持仓数据就先问**,绝不举例演示 —— 用户会当成对他的建议
2. 每笔交易给理由,且理由不能只是"回到目标"
3. **成本测算不许跳过**,并明确回答"值不值得调"
4. **不值得调就说不值得**,不要为了产出建议而建议
5. 只给调仓建议,不预测个股涨跌

## 需要的工具

- `portfolio_portfolio_rebalance` — 算调仓清单与换手成本
- `uzi_stock_deep_analysis` — 需要判断个别持仓基本面是否变化时
