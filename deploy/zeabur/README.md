# Zeabur 模板 · 发布与维护说明

这份文档写给**维护者**（要把模板发布到 Zeabur 模板市场的人）。
普通用户看 [`docs/deploy/zeabur.md`](../../docs/deploy/zeabur.md)。

| 文件 | 作用 |
|---|---|
| `template.yaml` | 模板本体。第一行的 `# yaml-language-server:` 指向官方 schema，VS Code 里直接有补全与报错 |
| `logo.png` | 512×512，`spec.icon` 与三个自家服务的 `icon` 都指它 |
| `cover.webp` | 1200×630，`spec.coverImage` |

## 发布命令

```bash
# 登录（会打开浏览器）
npx zeabur@latest auth login

# 部署一份到你自己的项目里试跑
npx zeabur@latest template deploy -f deploy/zeabur/template.yaml
```

> 官方文档只写了 `template deploy`，**没有**公开「发布到模板市场」的 CLI 子命令
> （2026-09-18 查 [CHECKLIST.md](https://github.com/zeabur/zeabur-template-doc/blob/main/docs/CHECKLIST.md)
> 与 [模板文档](https://zeabur.com/docs/en-US/template/template-in-code)）。
> 官方清单给的流程是「部署测试通过 → 向 zeabur 的模板仓库提 PR」。
> **上架的准确路径要拿到账号后按当时的文档再确认一次**，不要照这段猜。

## 部署时用户要填什么

**只有一项**：`PUBLIC_DOMAIN`（`type: DOMAIN`），Zeabur 会引导生成一个
`xxx.zeabur.app` 域名或绑定自有域名。

大模型配置**刻意不在这里要** —— 部署完打开域名，按五步向导填，
填完当场测三项（连通 / 对话 / 工具调用），测不通不让保存。

## 模板生成的五个随机值

| 变量 | 定义在哪个服务 | 谁要用 |
|---|---|---|
| `POSTGRES_PASSWORD` | postgres | api |
| `HUNTER_SETUP_TOKEN` | redis | api（向导第 0 步的口令，用户在 **api 服务的变量面板**里看） |
| `JWT_SECRET` | llm-shim | api + opencode（**必须同值**） |
| `HUNTER_INTERNAL_KEY` | api | api + web + opencode + paper + fin-worker（**必须同值**） |
| `FIN_PAPER_PASSWORD` | opencode | paper + 它的一次性 `provision-role` 步骤（**必须同值**） |

### 为什么 JWT_SECRET 定义在 llm-shim 上

因为 **`${PASSWORD}` 是「每个服务一个」**，不是「每次引用一个」
（[特殊变量文档](https://zeabur.com/docs/en-US/deploy/special-variables) 原文：
*A random password generated by Zeabur for each service*）。
一个服务里引用两次拿不到两个不同的值，而我们需要五把互不相同的密钥 ——
所以把它们「借位」定义在五个不同的服务上，再用 `expose: true` 共享出去。

借位的落点不是随手选的：**每个引用方都已经、且必须依赖被借位的那个服务**
（Zeabur 要求引用 expose 变量的服务把对方写进 `dependencies`），这样整张依赖图无环
（官方最佳实践明写「A 依賴 B，B 不能依賴 A」）。

依赖图：

```
postgres ─┬──► api ──┬──► opencode ──┬──► web
redis ────┤          │               └──► paper ──┐
llm-shim ─┘          ├──► paper ──────────────────┼──► fin-worker
                     │                            │
postgres ────────────┴──► temporal ──► temporalui └── (fin-worker 也依赖 temporal / api)
```

`deploy/tools/validate-templates.py` 会自动检查「引用的 `${VAR}` 有没有人
expose、引用方有没有声明依赖、依赖图有没有环」。

## 与本地 `docker-compose.yml` 的差异

| 项 | 本地 compose | Zeabur 模板 | 原因 |
|---|---|---|---|
| 密钥共享 | `hunter_secrets` 卷，api 写 / web / opencode 只读挂 | 模板生成 + `expose` 注入环境变量 | **Zeabur 不支持跨服务共享卷**（[compose 迁移指南](https://github.com/zeabur/zeabur-template-doc/blob/main/docs/DOCKER_COMPOSE_MIGRATION.md)「場景 1」） |
| `HUNTER_SINGLE_USER` | 默认 `1`（本机自用免登录） | **`0`** | 绑了公网域名，开着等于谁都能拿 admin token |
| 对外端口 | 本地各服务都映射到宿主（本机调试用） | 只有 web 的 3000 是 HTTP 端口；其余 `portForwarding.enabled: false` | 数据库和内部服务不该暴露到公网 |
| opencode 的卷 | Docker 具名卷（首次挂载会把镜像内容连属主一起拷进去） | 空目录 + `init` 容器 `chown 1001` | 官方指南原文：*Zeabur Volume defaults to empty directory*。不改属主，入口脚本会打印「会话数据目录不可写」并退出 |
| `LLM_SHIM_URL` | 不设也对（服务就叫 `llm-shim`） | **必须显式设** | 见下 |

### `LLM_SHIM_URL` 为什么必须设在 api 上

向导保存后，api 走 `PATCH /global/config` 把 provider 的 `baseURL` 推给 opencode，
那个值取自 **api 容器的** `LLM_SHIM_URL`（`services/opencode_admin.py`）。
不设就回落到硬编码的 `http://llm-shim:3999/v1`，而 Zeabur 的私有网络主机名是
`<服务名>.zeabur.internal`。

M3 在 Sealos 等价栈上实测过这个失败：**向导五步全绿、`engine-ready` 也返回 true，
但发消息永远收不到回复，日志里一条报错都没有** —— opencode 就卡在一个连不上的
baseURL 上。所以这一条列在这里，不要在「精简变量」时删掉它。

## 上架前必须拿到账号才能做的事

以下**本轮全部未做**（没有 Zeabur 账号）：

1. `npx zeabur@latest template deploy -f ...` 真部署一次，确认所有服务都起来
   （含智能交易的 paper / temporal / temporal-ui / fin-worker）。
2. 确认 **`${PASSWORD}` 的实际长度**。api 启动时会对 `JWT_SECRET < 32 字符`
   打 ERROR（`apps/api/boot.sh` 的弱密钥检测）。官方没公开长度，本轮按 32 实现。
   如果实际更短，要么接受那条告警，要么改用 `variables` 里 `type: PASSWORD`
   让用户自己填。
3. 确认 **一个服务里引用两次 `${PASSWORD}` 到底是不是同一个值**。本模板按
   「是」设计（所以才借位）。如果实际是「每次引用都不同」，借位可以取消、模板能简化。
4. 确认 `instructions` 里 `${HUNTER_SETUP_TOKEN}` 在控制台能正常显示出口令
   （schema 里 `ConnectionInstruction` 只要求 `title` / `content`）。
5. `icon` / `coverImage` 两个 URL 要在**合并进 main 之后**才可访问
   （指向 `raw.githubusercontent.com/.../main/...`），部署前 `curl -I` 确认 200。
6. 上架路径（模板市场 / PR 地址 / 是否需要审核）按当时的官方文档再核一次。

## 本地怎么验证（不需要账号）

```bash
# 1. 静态校验：官方 JSON Schema + 变量引用 + 依赖成环
python3 deploy/tools/validate-templates.py --online

# 2. 等价验证：把模板机械翻译成 compose，从空卷跑一遍
python3 deploy/tools/template-to-compose.py zeabur --out /tmp/t/zeabur --web-port 3210
cd /tmp/t/zeabur && docker compose up -d
```

翻译脚本用**平台自己的方式**生成随机密钥（每服务一把 `${PASSWORD}`）、照搬环境变量、
卷、依赖顺序与 `init` 规则，所以跑的就是模板本身的语义，人不能在中间「顺手改一下」。
它盖不到的部分（控制台表单、域名绑定、计费、镜像拉取加速）写在脚本文件头。
